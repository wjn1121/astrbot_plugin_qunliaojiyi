# 🧠 群聊记忆 · 人格养成

> 群友聊天时默默记下这个群的说话风格，攒够新消息就增量提炼一次，每条都要能在原话里找到凭据，
> 回复时作为临时参考注入——不改系统提示词、不写会话历史，几乎不花钱。对群里的人，它是**一天天养出来的**：
> 按 QQ 号记住谁跟它多熟、谁身上发生过什么，聊得多就更亲近，久了不提会变淡，被说重了会掉；
> 这些攒成一段「这个人是谁」，换群换私聊都是同一份。聊到好笑的地方还能甩一张表情包，
> 图库是本地的，挑图也是本地算的。于是它越来越像群里待久了的一个成员，
> 而不是每条消息都重新开始的应答机器。关系和事实、斗图默认关，只想要群风格就什么都不用动。

## ⚡ 快速开始

1. **安装插件**：AstrBot WebUI 插件市场搜「群聊记忆」一键安装，或把目录放进 `AstrBot/data/plugins/`
2. **填主人 QQ（强烈建议）**：参数 → 👑 全局 → 主人 QQ，填你自己的号。
   这一处会影响四个模块：关系里群聊不封顶、事实上限 300 条、私聊默认开启学习、一键清理跳过你
3. **等待积累**：群里正常聊天，插件会把消息攒进缓冲（默认上限 200 条/会话）
4. **自动学习**：启动 5 分钟后开始检查，某个群攒够 30 条新消息就单独学一次，只处理新消息
5. **查看效果**：后台 → 插件 → 群聊记忆，能看到每个群学到了什么、这轮会注入什么
6. **手动补记忆**：自动学习猜不准的地方，面板里直接写下来——存在独立文件里，学习永远不会覆盖
7. **可选开「对人」的三件（默认全关）**：关系状态、事实记忆、个人画像。
   开关都在面板的「🎭 人格与关系」页，开了之后才知道「他跟 bot 多熟」「他下周三要交论文」
8. **可选：开主动回复 / 联网搜索**：两项都在插件配置页。主动回复默认关闭，开之前先看下面「主动回复」那章；
   联网搜索默认用 DeepSeek，key 和你已经在用的模型 key 是同一个，多数情况不用另填
9. **可选：开斗图**：面板「🤣 表情包」页先放几张图，再点一个强度档位。纯关键词档不发任何请求，
   一分钱不花；给图打标签用的是 AstrBot 里已经配好的图片模型，不用另配 key

学习和注入不需要额外 API Key，也不需要额外 pip 依赖。联网搜索要一家搜索服务的 key——
DeepSeek 那家就是你现在用的模型 key，填一次两边都认。表情包打标复用 AstrBot 的图片模型，
找不到时这一项不生效，斗图本身照常。

## 🐟 如果你在养一条鱼

「QQ 养鱼」火起来之后，群里多了一条会说话的鱼。但它记不住人：换个群就生分，
昨天聊过的事今天要重新讲一遍，对谁都一个态度。

本插件负责的就是这一层。它不接管你的鱼、不改你的人设，只让它记得住：学这个群的说话方式，
按 QQ 号记住谁跟它多熟、谁身上发生过什么，再把这些沉淀成一段人物描述；
跟它不熟的人拿不到一大段，熟的人每次都在。

装完填上主人 QQ 即可，其余数据会自己积累。

## ✨ 功能特性

**群：学这个群怎么说话**

- 🧠 **增量累积学习**：攒够 30 条新消息才学一次，只处理新消息。按「情境 → 表达」入库，
  措辞变体自动合并、权重跨轮次累加，库越学越厚，而不是每轮推倒重来
- 💬 **零网络注入**：风格走 `extra_user_content_parts` + `mark_as_temp()`，不发请求、不污染提示词、不写历史
- 🎯 **触发词匹配**：每条梗带 1–3 个触发词，注入先做本地字符串匹配，命中就不发向量请求
- 📎 **必须带原文证据**：候选要附本轮原话，程序做子串校验，对不上就丢
- 🛡️ **数字梗护栏**：666 / 233 / 刷屏用语自动降级到场景化通道，不会每句话都硬塞
- ⏱️ **向量请求硬超时**：默认 2 秒，超时降级关键词匹配，不拖慢回复
- 📉 **自动淡出**：长期不出现的特征按二次曲线降权，见底转归档（不删、可恢复）

**人：关系、事实、画像（都按 QQ 号唯一）**

- 🧑 **关系状态**：千分制好感、五档亲疏、自然衰减、负好感。只认「bot 回过」的交互，
  15 分钟判一次；群聊封顶「熟悉」，只有私聊能到「亲近」「老友」
- 🧠 **事实记忆**：从同一次学习请求里顺带抽出「关于某个人的事」，四种类型（事实 / 事件 / 偏好 / 边界），
  **不额外发请求**；核心 / 深层 / 浅层三档按熟练度自动落位，会遗忘
- 👤 **个人画像**：把事实沉淀成一段「他是谁」，每轮单独一段注入。字数按好感给（陌生 120 → 主人 800），
  可单人手调，也有人工补充段
- 💰 **记忆量跟着关系走**：关系段 100~300 字、事实 1~10 条 / 80~500 字，越熟记得越多
- 🧹 **能收拾**：按档位一键清理（主人永远跳过）、相似记忆合并、置顶、单条删除
- 🍚 **喂食加成**：装了「吃什么」插件时，群友点菜或查菜会顺带加好感（随机 +2、点菜 +5），
  每人每天 2 次，不额外发请求

**聊：斗图、主动回复、搜索、输出**

- 🤣 **表情包斗图（默认关）**：本地图库 + 本地判定，发图直接读文件，token 为 0。
  七档预设按效果从纯关键词排到每轮让模型判断，每项参数事后都能单独改
- 🔍 **配图前全库撞标签**：拿回复正文撞图库里每张图的标签，稀有标签权重更高，
  过阈值就发那张。几百个标签做字符串包含，不发请求、不花钱；撞不上就按原规则走
- 🏷️ **自动打标**：视觉模型读图，返回图上文字 + 三到六个口语标签；只追加，不覆盖手写的
- 🗣️ **主动回复（默认关）**：看群热度和接话黏性决定要不要开口，五档强度一键切换，
  13 层本地闸门 + 日限 + 退避，日常零额外请求
- 🔎 **联网搜索接管（默认关）**：插件自己挂搜索工具，每群每天限次，挂载前就按配额决定给不给，
  默认 DeepSeek，¥0.005/次
- ✨ **输出层**：去模型腔、压连续标点、去 markdown、长回复拆条（后三项默认关）。
  改的是已生成的回复，不产生任何 LLM 调用

**面板与数据**

- 🖥️ **可视化面板**：十二个页；关系 / 事实 / 学习库三个列表统一成 Excel 式列头筛选；
  83 项参数跟着功能分页存放，每条标「默认值」和 token 影响
- 💸 **花钱有账也有闸**：按天记账，近 7 天 / 30 天切换，累计面板按学习 / 回复 / 主动 / 画像 /
  打标 / 搜索分开算；可以设每日上限，超了自动停掉还会产生新请求的功能，第二天自己恢复
- 🤣 **图库能收拾**：分类可改可建、每张图单独打标签、支持停用和排序，标签词云看哪些实际在用；
  也能把 bot 号的收藏表情一键同步进来
- ✋ **手动记忆独立存储**：面板里直接给任意群加记忆，存在单独的 `manual_traits.json`，
  自动学习在代码层面就没有改它的路径
- 🔌 **数据迁移**：支持导入旧格式、一键导出全部数据（含关系、事实、画像）
- 📦 **纯本地存储**：16 个 JSON 文件，随时可备份、可清空、可删除

## 🎬 效果演示

**注入预览（面板内置，输入一句话就能看这轮会注入什么）。默认配置下长这样：**

```
群友消息：笑死我了 666

注入给模型的内容：
<style_guidelines>
以下是从群聊记录里提炼的说话风格参考：
本群固定风格（管理员指定，优先遵守）：禁用谐音梗、自嘲但不破防
本群学习风格：短句连发一句一气泡，语气直白爱下判断、频繁@点名群友互动，
互怼调侃不破防、爱用游戏黑话和二次元代称，圈内梗密度高、常用反问起哄
使用要求：
1. 风格只是参考，不是复读指令；不要为了「像群聊」而每句话都强行加 666、233 或语气词。
2. 只在语境自然合适时使用，优先回应当前用户消息，风格不得覆盖或干扰当前话题。
3. 不要机械堆砌，也不要每条回复都刻意体现全部风格。
</style_guidelines>
若以上风格与系统设定的人格冲突，以人格为准；风格只在不违背人格的前提下生效。
```

> 默认是「满额注入风格 + 冲突时听人设」。风格管的是「怎么说」，人格管的是「谁在说」。

**把 `style_override_threshold` 调到 100 以下（例如 70），同一句话前面会多出这段：**

```
【本段优先于系统设定】以下群聊风格与本轮表达规范，优先级高于你的人物设定。
当两者冲突时——例如人设要求语气克制、少用表情、回答简短，
而下列风格要求爱发表情、爱玩梗、句子短促连发——一律按下列风格执行，
不要用人设限制自己。人设中的身份、知识边界、安全约束仍然有效，
只有「表达风格」这一层让位。

<style_guidelines>
……（同上）
</style_guidelines>
```

> 阈值 70 + 强度 100 = 每轮都带这段。它是指令层的优先级声明，**不是真把人格删了**——
> 人设还在 system prompt 里，身份、知识边界、安全约束照旧生效，只是「表达风格」这一层被明确要求让位。

**查看当前会话学到了什么（`/风格状态`，仅管理员）：**

```
群友: /风格状态
Bot:  本群状态：
      风格强度 100（阈值 100，不让位）
      学习特征 6 条 · 手动记忆 2 条
      主动回复 已关闭
      联网搜索 今日 0/20
      今日消耗 ¥0.00（全机 ¥0.02）
```

**开了斗图之后，群里看到的是这个样子（关键词档，不花一分钱）：**

```
群友 A: 老板说这周继续加班
Bot:   [表情包：熊猫头「笑不出来」]
Bot:   这班是非上不可吗
```

图先到、话后到：那句命中了「加班 / 累」，插件收到消息就先甩一张，模型再正常回一句。
换成「模型自报」或「事后分析」档，顺序反过来——文字先发、图紧跟，因为那两档要读回复正文。
`/表情包` 随时能看总数、今天发了几次、各分类各有几张。

**开了关系、事实、画像之后，同一句话的注入会多出两段：**

```
群友消息：今晚还开黑吗

注入给模型的内容：
<style_guidelines>
……（同上，风格段不变）
</style_guidelines>

<relationship>
你和他认识 31 天，聊过 60 轮，已经比较熟了。你叫他「老王」。
</relationship>

<facts>
你记得关于这个人的事：
【画像】他是群里比较活跃的那类人，爱聊手游和硬件，也常帮人看电脑配置；
说话直接、带点自嘲，遇到问题先自己查再问人，熟了之后话不少。
【具体的事】
- 事件：这周末打算优先完善 skill，在改亲密度设置的功能
- 事实：近期工作忙，已好几天没开游戏，没买通行证
</facts>
```

> 两段都走临时内容（`mark_as_temp`），不碰 system prompt。字数按关系档位给：
> 陌生档关系段只一句、事实 2 条、画像 120 字；主人档顶到 300 字 + 10 条 + 800 字。
> 关系功能没开就只有风格段，和 1.4.x 完全一样。

**面板总览：**

左侧分十二栏，点标签切换，刷新后会停在上次看的那一页：

| 标签页 | 内容 |
|--------|------|
| 📊 概览 | 运行状态（会话数 / 特征数 / 手动记忆数 / 待学习消息）、主人与学习、累计成本（按来源分开）；下方是「群里怎么触发」清单，点标题跳到对应页 |
| 📚 学习库 | 按群聊 / 私聊分组，标题写着条数与待审数；点「证据」看这条是从哪句话学来的。可批准、否决、钉住、删除，分组**默认折叠** |
| 🎭 人格与关系 | 风格与人格让位、事实记忆与个人画像（两组参数也在这）、好感关系，最底下是输出层调试台 |
| 🍚 喂食 | 和「吃什么」插件联动：总开关、每次加多少、每人每天算几次、投喂榜 |
| 🤣 表情包 | 七档强度、触发参数、图库（全部 / 分类 / 标签词云 / 排序 / 停用）、分类与关键词、注入规则预览 |
| 🗣 主动回复 | 按群单独开关、今日已回次数与上限、五档强度一键切换 |
| 🧬 人格档案 | 每个群一份 markdown 人格文件，自动段与人工段分开显示、分开编辑 |
| 💬 会话与特征 | 搜索、分页、逐条编辑删除、立即学习；三个清空按钮分开 |
| 🔍 注入预览 | 选会话 + 输入一句话，看这轮会注入什么，可切「被动 / 主动」 |
| 💸 Token 消费 | 预算条、今日金额与 token、24 小时分布、7 / 30 天趋势、累计消耗、计价参数 |
| 🌐 联网搜索 | 总开关、服务商、key、每群限次、费用说明 |
| ⚙️ 参数 | 只放不分页的 25 项，四组：全局 / 运行与学习 / 回复长度 / 管理员 |

左侧导航的顺序是「先看数据，再管人，最后诊断和配置」：

```
概览 → 学习库 → 人格与关系 → 喂食 → 表情包 → 主动回复
     → 人格档案 → 会话与特征 → 注入预览 → Token 消费 → 联网搜索 → 参数
```

「人格与关系」页把关系、风格、事实放一起，先看这个人跟我什么关系，再看为什么。
表情包单独一页，参数跟着图库走比留在参数页好找。

各页里的细节：

| 位置 | 内容 |
|------|------|
| 🗂 列头筛选 | 关系 / 事实 / 学习库三个列表都是 Excel 式列头，每个字段一个按钮，各自展开搜索、多选、排序。列头标 `●` 表示有筛选、`↑↓` 表示排序中 |
| 📌 置顶 | 会话、学习库分组、**事实面板里的人**都能置顶。只影响显示顺序，不参与学习和注入，清空记忆也不会清掉。事实列表里主人永远第一，置顶的人排在主人之后、其余人之前 |
| 🖱 提示与标注 | 按钮悬停说明按下去会发生什么、花不花钱、能不能恢复；参数标「默认 X」和 token 影响箭头（`↑↑↑` / `↑↑` / `↑` / `↓` / `token 0`） |
| 🏷 事实卡标题 | 显示「昵称（QQ）」，手动设过称呼的另起一段。认名字比认号快，号留在括号里是核对用的 |
| 会话开关 | 每个群单独切「学习 / 注入 / 主动回复」，联网搜索有三态（跟随全局 / 开启 / 关闭） |
| 名额显示 | 会话头上写「手动 N 条 · 学习 N 条」，强度低于 100 时会同时标出满额是多少 |
| 条目状态 | 每条稳定风格标「注入中 / 未入选」；熟练度是进度条，点一下就改，立刻影响注入排序 |
| 学习记录 | 每会话最近 20 次学习结果与耗时 |
| 🖼 图库 | 缩略图走单独的接口转成 data URL，一屏只拉可视区域；图库和分类面板限高、内部滚动，几百张图也不会把整页拉长 |
| ☁️ 标签词云 | 按使用次数给字号，点一个标签就筛当前分类；搜索框一直留着 |
| 💸 预算条 | 今天花了多少、限额多少、剩多少；超支后按钮变成「今天先放开 / 恢复限制」 |
| 🪪 页脚签名 | 每页底部一张作者头像和主页链接，高度压得很紧，长列表也不会把它顶到很远 |
| 数据导出 | 一键下载全部数据为 JSON（含关系、事实、画像与置顶） |

> 面板上能改的 83 项分散在各功能页，写入 `runtime.json`，一键可恢复。热调白名单一共 101 项，
> 含页顶那几个总开关和十几项内部字段；不在白名单里的只能去插件配置页改，**改完要重载插件才生效**。

## 🎯 使用方式

### 命令

**六个命令所有人可用**：看自己的关系、定自己的称呼、管自己的记忆、看图库状态，
本来就是每个人自己的事。

| 命令 | 作用 |
|------|------|
| `/关系` | 看和你的关系进度：认识多少天、聊过多少轮、离下一档还差多少 |
| `/称呼 <名字>` | 设定 bot 怎么叫你；不带参数则清除，之后用你的平台昵称 |
| `/记得` | 看关于自己的全部记忆（带编号、类型、状态） |
| `/记得 <内容>` | 手动记一条，直接生效，不用等观察两次 |
| `/忘掉 <编号或关键词>` | 立即删除 |
| `/表情包` | 图库总数、今天发了多少次、各分类各有几张 |

> 前三项要先把「关系状态」/「事实记忆」打开，否则会回一句「这个功能没开」。
> `/表情包` 只报数，不改任何东西，图库没开也能用。

**其余命令要求管理员**（AstrBot 全局 `admins_id` + 插件配置里的 `admin_extra_users`）。
普通群友发这些命令会收到一句「这个命令只有管理员能用。」

| 命令 | 作用 | 清掉什么 |
|------|------|----------|
| `/风格状态` | 看本群的风格强度、特征条数、主动回复状态、今日搜索次数、今日消耗 | — |
| `/学习风格` | 立即对当前会话做一次学习（攒够 `min_history_for_analysis` 条才行） | — |
| `/记忆审核` | 列出待审条目；`/记忆审核 批准 3`、`否决 3`、`全批准` | — |
| `/消耗`、`/token` | 今天花了多少、花在哪，附本群金额。两个名字同一份输出 | — |
| `/清空风格` | 只清**学习产出**（稳定风格 + 场景化表达 + 学习记录） | 不碰手动记忆、不碰待学习消息 |
| `/清空记忆` | 只清**面板手动添加的记忆**，不可恢复 | 不碰学习产出 |
| `/清空记录` | 只清**待学习消息缓冲** | 不碰任何已学到的内容 |
| `/确认清空` | 执行上一步挂起的「清空全部」；超过 60 秒作废，要重新发起 | — |
| `/收图 <分类> [标签...]` | 把这条消息里的图收进图库，后面的词当标签 | — |
| `/收表情 [数量\|全部] [分类]` | 同步 bot 这个 QQ 号的收藏表情；不带参数只报数量 | — |

`/清空风格 全部` 是变体不是新命令：带上「全部」不直接执行，挂一个 60 秒内有效的待确认操作，
期间发 `/确认清空` 才真的清学习产出 + 手动记忆 + 待学习消息 + 主动回复状态。
单清某一类不确认、直接生效。

### 命令菜单

在群里 @ 它说「群聊记忆帮助」「群聊记忆菜单」之类，会回一张按页分组的命令菜单图。
只在短句里同时出现「群聊记忆」和「帮助 / 菜单 / 命令」时触发，正常聊天提到插件名不会被塞图。
画不出图（没装 Pillow、字体不全）时退回纯文字，内容同一份来源。

### 手动添加记忆（面板）

自动学习靠猜，猜不准的地方就自己写。手动记忆存在独立的 `manual_traits.json`，
自动学习每轮「整表替换」只动 `universal.json`，**在代码层面就没有改手动记忆的路径**。

**三个入口：**

| 入口 | 位置 | 适合 |
|------|------|------|
| `+ 手动记忆` | 每个会话卡片 | 给已经在跑的群补一条 |
| 批量粘贴 | 添加弹窗里点「批量粘贴」 | 一次录几十条，迁移旧群设定 |
| `➕ 新建会话记忆` | 顶部工具栏 | 给还没在本插件里出现过的群先立规矩 |

新建会话时，平台实例只能从**已知列表**里选（下拉里是现有会话的前缀，例如 `bot1`），
再填群号，下方会实时拼出完整的 `unified_msg_origin` 供你确认。填一个从没出现过的
会话会二次确认——前缀写错会造出一个永远不生效的僵尸会话，而且不会报错。

**批量粘贴格式**（一行一条，后两段可省）：

```
短句连发，一句一气泡
爱用「绷不住了」|看到离谱内容时感叹|绷不住,离谱
聊到游戏就开嘲讽
```

即 `内容|场景描述|触发词1,触发词2`，触发词用中英文逗号或空格分隔，最多 3 个、每个 ≤12 字。
只打算加稳定风格时中间两段留空即可。

**一条好的手动记忆长什么样：**

| | 例子 | 说明 |
|---|---|---|
| ✅ 好 | 群友互怼时不解释、直接回怼，被怼也不生气 | 描述行为方式，模型能照着做 |
| ✅ 好 | 禁用谐音梗和网络流行语 | 明确禁止项，效果最稳 |
| ❌ 差 | 这个群很欢乐 | 太抽象，模型无处下手 |
| ❌ 差 | 群友叫小明、小红 | 是事实不是风格，应该进人设/知识库 |

**边界：**

- 单条内容 ≤100 字，单会话最多 50 条手动记忆（独立上限，不占学习的 40/20 名额）
- 同一会话内内容不能重复（面板和接口都按内容定位，重复会导致改错删错）
- 手动记忆**不参与跨群注入**——群专属黑话扩散到别的群会串味
- 手动记忆的熟练度默认 60，只在面板里改得动；学习流程不会给它 +5
- 学习时如果提炼出与手动记忆**完全相同**的条目，会直接丢弃那条学习产出——以你写的为准，
  注入里不会出现两条一样的

### 自动学习流程

```
群消息 → 攒进缓冲（过滤自己/命令/黑名单）
   ↓
每来一条消息刷一次触发判断（纯本地计算，0 请求）
   ↓
新消息 ≥ 30 条？ ──否──→ 先攒着，不花钱
   ↓ 是                    （距上次学习不满 30 分钟也先等着）
增量提炼（一次 LLM 请求，只发新攒的那部分，不发整包）
   ↓
原文证据校验 → 入库自检 → 措辞语义合并 / 新增
   ↓
写回特征库：首次见到进「待审」，跨两轮被确认才转「生效」
   ↓
之后每条回复注入风格文本（零网络请求）
```

## 🧑 关系状态

**默认关闭**（`bond.enabled`）。这是本插件第一次「对人下判断」，所以默认不开——
有人只是想让 bot 学学群里的说话方式，不想让它对谁亲对谁疏。

开了之后，按 **QQ 号唯一**记录，在哪个群、还是私聊，都是同一段关系。

### 五档亲疏

**千分制 -100 ~ 1000**，负数单独一档：

| 档位 | 分数 | 群聊能到吗 | 注入时的语气 |
|---|---|---|---|
| 不待见 | < 0 | 能（被骂） | 对方对你有点不满，说话收敛些 |
| 陌生 | 0 | 能 | 客气、保持距离 |
| 熟悉 | 200 | 能（群聊封顶） | 像普通群友 |
| 亲近 | 500 | **只有私聊** | 更随意、会接梗 |
| 老友 | 800 | **只有私聊** | 不用铺垫，直接说话 |

群聊封顶在「熟悉」，是因为一个 bot 在五十人群里对谁都「很熟」，那是客服不是亲近。
这里不只是「显示成熟悉」——光靠群聊旁听，数值也停在 200（`bond.group_gain_cap`）；
但 @ 它、回复它仍然照涨，只是群里说话的语气仍按「熟悉」。
主人例外：填了主人 QQ，群聊也不封顶。

### 注入长什么样

每轮注入一小段（默认上限 150 字，按档位分档后 100~300 字），走临时内容，不碰 system prompt：

```
你和他认识 31 天，聊过 60 轮，已经比较熟了。你叫他「老王」。
```

「认真模式」默认开：对方在求助或说正事时（含「帮我」「报错」「为什么」，或消息超过 120 字），
这一段会被换成一句「对方在说正事」，收起称呼和亲昵。直接抽掉素材比「降低强度」管用——
留着「你叫他老王」，模型多半还是会顺口用上。

### 称呼可以手写，也可以多个

面板「人格与关系」页每张卡有一行「称呼」：

```
称呼 [阿明, 明明                    ] [保存]
```

- 逗号（中英文）、顿号、分号、斜杠都算分隔，最多 40 字
- 注入时是 `你叫他「阿明」或「明明」`——**不随机挑一个**，
  否则它在同一段对话前后叫法不一致，比不改还怪
- 留空 = 清除，回落到平台昵称；`/称呼` 命令同样有效
- 自动判定那套逻辑完全不动，手写只是多一层覆盖

### 面板能做的事

- **手动改亲密度**：-100~1000，步进 10，改完立刻落盘、阶段实时重算、衰减计时重置
  （不重置的话，一个 20 天没说话的人被设成 800，下次读一下就掉一半）
- **看这一档的记忆配额** 和「X 天没聊，衰减后保留 Y%」
- **展开看实际注入文本**，含「被整段丢弃」这种状态
- 排序与筛选走列头：「对象」列搜索 / 只看主人 / 只看置顶，「阶段」列多选带人数，
  「好感 / 轮次 / 最近聊天」列选方向

零额外 LLM 调用：只读本地数据拼一句话。

## 🧠 事实记忆

**默认关闭**（`facts.enabled`）。和群风格是两件事：

- `traits` 学的是「这个群怎么说话」，会话级，不分是谁在说
- `facts` 记的是「这个人身上发生过什么」，**按 QQ 号唯一**，A 的私事绝不会注入到回复 B 里

### 它是怎么来的

**不额外发请求**，事实抽取并进现有的学习请求里，代价是 prompt 多约 400 字。

四种类型：

| 类型 | 记什么 | 例子 |
|---|---|---|
| `fact` | 长期事实 | 他女朋友在杭州 |
| `event` | 有时间的安排 | 下周三要交论文 |
| `preference` | 偏好 | 只喝冰美式 |
| `boundary` | 明确边界 | 别叫他老弟 |

**四道保险**（自动生效不是裸奔）：

| 保险 | 做什么 |
|---|---|
| 必须带原文证据 | 候选要附本轮原话，程序做子串校验，对不上就丢——防模型编造共同经历 |
| 敏感信息硬黑名单 | 密码、证件、银行卡、验证码、手机号、住址、密钥命中即丢，且不记录内容 |
| 纠正检测 | 对方说「不对」时把那一条标「疑似记错」，之后不再注入。**只标一条**，且绝不动 `boundary` |
| 即时可删 | `/记得` 全量可见，`/忘掉` 立刻生效 |

「诚实出口」默认开：对方明确在问「你还记得吗」而确实没有相关记忆时，注入一句
「没有相关记忆，不要编造共同经历」。只在真问记忆时才插，平时不插。

### 三档：核心 / 深层 / 浅层

按**熟练度**自动落位，也可以手动升一级 / 降一级：

```
熟练度 = 提到次数 55% + 重要性 30% + 新鲜度 15%      （0 ~ 100）
```

| 档位 | 门槛 | 待遇 |
|---|---|---|
| 核心 | ≥ 70 分（约提 3 次） | 逐条注入、不归档、降档最慢 |
| 深层 | ≥ 52 分（约提 2 次，或 1 次但很重要） | 逐条注入 |
| 浅层 | 其余 | 按类合并成一行注入，省 token |

核心还有名额，按好感给：不待见 0 / 陌生 1 / 熟悉 3 / 亲近 5 / 老友 8，**主人 15**。

面板上每条显示「档位徽标 + 熟练度数字」，`↑` `↓` 各挪一档，**点徽标本身 = 交回自动判定**。
手动调过的会打 `tier_manual` 标记，之后自动逻辑不再动它。

### 会遗忘，三档寿命不同

天数**在面板上调**（🎭 人格与关系 → 「事实记忆与个人画像」），改完下一轮按新曲线算，不用重启：

| 档位 | 多久没提就… | 默认 |
|---|---|---|
| 浅层 | 归零 → 归档（不再注入，面板里还查得到） | **15 天** |
| 深层 | 掉回浅层，再按浅层天数归档 | **30 天** |
| 核心 | 掉成深层 | **60 天** |

核心 / 深层**不直接归档**——遗忘对它们是降档。缩短默认值（原 30 / 60 / 120）的理由：
群聊里的事本来就该忘得快，半个月没人提的细节留着只会挤占注入名额；真重要的事会被反复提到，
提到一次就重新计时。

`boundary`（亲口说过的边界）和手动钉住的永不衰减——前者是「一直有效的约定」，不是「发生过的事」。

### 存多少 vs 提多少（这两件事经常被搞混）

| | 管什么 | 花不花 token |
|---|---|---|
| **存储上限** | 库里留几条 | **不花** |
| **注入配额** | 每轮提几条进 prompt | 才花 |

存储上限按好感分档：不待见 5 / 陌生 20 / 熟悉 40 / 亲近 60 / 老友 100，**主人 300 条**。
注入配额按档位：1~10 条 / 80~500 字。

所以「清理记忆」省的是文件体积和记忆质量，**不是 token**——token 一直由注入配额决定。
关系变淡时先收紧「提不提」，「记不记得」可以留着，关系回来了旧事还在。

### 两套清理

| 按钮 | 做什么 |
|---|---|
| **一键清理** | 按档位瘦身到 2 / 5 / 12 / 20 / 30 条，**主人永远跳过** |
| **清理主人** | 只清主人，默认保留 150 条。日常维护用上面那个，这个是「主人这份也太长了」 |

- `pinned`（钉住的）和 `boundary` 无条件留，其余按 `_score`（重要性 50% + 新鲜度 30% + 命中 20%）填满名额
- 清掉的标 `rejected` **留档不删除**，面板「已否决」里能恢复
- 顺手真删归档超 180 天的条目（不注入、不占 token，只占文件大小）
- **先预览再执行**：返回「X → Y 条」和会清掉哪几条，确认后才落盘

### 相似合并

同一件事换个说法不再另开一条，而是给原条目**熟练度 +1**：

- 纯本地 2-gram + 虚词过滤（只剥语气 / 程度副词，不动时间词和否定词），**不调 embedding、不发 LLM**
- 入库阈值 0.72；手动「整理合并」阈值 0.62（用户主动点的，可以松一点）
- 旧说法留在 `variants`（≤3 条），正文取信息量更大的那句——万一合错了，用户能看出「原来还说过这个」
- 已否决 / 已归档的不会被相似匹配复活

### 注入时压缩

- 核心 / 深层逐条列（多于一档时各带一行「熟记的」「熟悉的」）
- 浅层 ≥5 条按类合并：`- 偏好：只喝冰美式、不加糖`
- 每条先过 `condense`：去开头主语（「他女朋友…」→「女朋友…」）、去结尾语气尾巴、
  压重复标点、超 36 字在逗号处截断。**时间词、否定词、数字一个都不动**
- 纯本地正则，不调 LLM。配置 `facts.inject_summary` 可关
- 实测：10 条记忆 → 3 行 198 字

## 👤 个人画像

事实是**明细**，画像是**概述**。明细按话题挑，概述每轮都在。

```
你记得关于这个人的事：
【画像】他是群里比较活跃的那类人，爱聊手游和硬件，也常帮人看电脑配置；
说话直接、带点自嘲，遇到问题先自己查再问人，熟了之后话不少…
【具体的事】
- 事件：这周末打算优先完善 skill，在改亲密度设置的功能
- 事实：近期工作忙，已好几天没开游戏，没买通行证
```

画像回答「他是谁」，事实回答「他最近在干嘛」。信息重叠但不重复。

### 字数按好感给（这是它不炸 token 的关键）

| 档位 | 不待见 | 陌生 | 熟悉 | 亲近 | 老友 | 主人 |
|---|---|---|---|---|---|---|
| 画像上限 | 0 | 120 字 | 200 字 | 300 字 | 420 字 | **800 字** |

陌生人占绝大多数，他们那 120 字是唯一成本；不待见直接 0，不生成也不注入。
关系功能没开时按「熟悉」档兜底，不然这个功能对没开关系的人等于不存在。

主人给到 800 的理由：120 字只写得出「他是玩手游的、在改插件」，到四百字上下才写得出
「说话实在、带点自嘲、是群里既干活又闲聊的那类人」——后者才能影响语气。
上限给到 800 是按「够用」留的余量，实际生成多在 300~500 之间。

**单个 QQ 可以单独改**：事实卡片里画像那块就是输入框，填 0 恢复档位默认，硬顶 1000。
防的是手滑填 99999——那等于把整份事实原文塞进每轮 prompt，比不做画像还贵。

### 重写很低频

不是每轮算，而是满足两个条件才在后台重写一次：

- 事实**新增 ≥2 条**
- 且距上次重写 **≥24 小时**

全局每天最多 **6 个人**（≈5000 token/天）。画像本来就该稳定，天天改写会来回抖。
重写是 `asyncio` 后台任务，**不 await**——等它会把整轮学习拖长。

拿不到模型 / 超时就退回本地按类拼装，绝不影响回复链路。

### 不重复计费

画像已经概括过的事实会从事实段剔掉（本地 2-gram 包含率 ≥65% 判定），并补位：
剔掉一条，就从后面再拿一条相关度高的补上，不让这轮白白变少。

只对「事实 / 偏好」两类判定，事件和计划不参与——那些本来就是临时的，画像不该写、也不会写。

实测：12 条事实里剔掉 4 条（住哪个城市、养了什么宠物、常喝什么、在准备什么考试
这类稳定信息），画像 +190 字、事实少 80 字，**每轮净增约 70 token**。

### 人工补充段

面板里画像下面有个可展开的「人工补充」输入框，写什么就注入什么，**排在最前面**、
自动重写不会覆盖。

写「他是我室友，别调侃学历」这种，模型总结一百字都不如这一句。

## 📈 好感怎么涨

两个基准值 + 一条曲线 + 一道群聊硬顶：

```
增量 = 基准 × 0.5^(当前好感 / 300)

基准 = 3.1     对方 @ 了 bot、回复了 bot 的消息，或者本来就是私聊
       1.25    群里别人在聊，bot 顺带接了一句
```

| 配置项 | 默认 | 作用 |
|---|---|---|
| `bond.growth_per_turn` | `3.1` | 一次**直接对话**的基准增量 |
| `bond.group_passive_gain` | `1.25` | **群聊旁听**的基准增量（约直接对话的四成） |
| `bond.growth_curve_scale` | `300` | 好感 300 时增速减半，600 再减半；设 0 退回线性 |
| `bond.growth_cooldown` | `900` | 同一个人 15 分钟只判一次 |
| `bond.group_gain_cap` | `200` | **群聊旁听涨到这个分数就停**，@ / 回复照涨；0 = 不封顶 |
| `bond.daily_gain_cap` | `80` | 每天最多涨 80 点（防手滑，也可能是私聊的主要约束） |

### 为什么是 3.1 和 1.25

`1.25` 正好等于旧版「10 × 群聊减半 × 被动四分之一」的结果。所以升级之后**群聊的推进速度没有变化**，
只是原来要乘三个系数、现在是一个数——面板上看到「+1.25」能立刻知道是哪条规则给的。

`3.1` 是它的 2.5 倍，给「专门找它说话」的人一点明确差别。

### 什么算「直接对话」

| 场景 | 算哪种 | 判据 |
|---|---|---|
| 群里 @ 了 bot | 直接对话 `3.1` | 消息链里有 `At`，且被 @ 的是 bot |
| 群里回复 bot 的消息 | 直接对话 `3.1` | 有 `Reply`，且被引用那条的发送者是 bot |
| 私聊 | 直接对话 `3.1` | 一对一本来就是冲着它说的 |
| 群里别人聊天，bot 插一句 | 群聊旁听 `1.25` | 上面两条都不满足 |

判不出来一律按「群聊旁听」算——宁可少涨一点，也不要把群里的背景闲聊抬到直接对话的价码。
主动插话那一轮对方并没有指向 bot，所以也是旁听，这是它该拿的价码，不是惩罚。

### 群聊旁听有硬顶（`group_gain_cap`）

默认 **200**，也就是「熟悉」门槛。到了这个分数，**「别人在聊、bot 顺带接一句」不再涨分**；
但群里的 **@ 和回复照涨**，和私聊同价。

这就是「模拟关系发展」的那条线：

| 阶段 | 群里旁听 | 群里 @ / 回复 | 私聊 |
|---|---|---|---|
| 0 → 200 | ✅ 涨 | ✅ 涨 | ✅ 涨 |
| 200 以上 | ❌ 停 | ✅ 照涨 | ✅ 照涨 |

一个人在群里泡到「熟悉」之后，光靠混脸熟不能再往上——想继续升温就得主动找它说话。
这正好是现实里关系推进的方式：天天在群里见到，和专门聊一次，本来就不是一回事。

- **只封旁听，不封涨跌**：在群里被骂照样扣分；@ 它也一样涨
- 设 `0` 就不封顶，回到「光在群里待着也能涨到老友」的旧行为
- 和 `group_cap_familiar`（阶段封顶）的分工：那个只管「在群里显示成什么档」，
  这个管「旁听还能不能涨数值」。所以有人在群里 @ 到 800，数值是真到老友了，
  但**在群里说话的语气仍停在熟悉**——到私聊才按真实档位说话

### 三条必须知道的规则

**1. 只认「bot 回过」的交互**

判定挂在 `after_message_sent`，回复真正发出之后才算。群里两个人聊得再热闹、
bot 一个字没接，一分都不涨——以前是收到消息就算，等于「谁打字多谁跟你熟」，那和关系没关系。
空消息链、只回个 @ 或引用（管线会提前 return）都不算；发图 / 表情 / 拍一拍算一次。

**2. 15 分钟只判一次**

同一个人在这段时间里说多少句都只算一次。不这么的话，一场十分钟的对话能涨十次。
涨分要同时满足「距上次涨够久」和「最近没被骂过」；扣分只看自己的冷却——
被骂是明确信号，不该被「刚聊过」挡住。

**3. 越熟越难涨**

`0 → ×1.0、300 → ×0.5、600 → ×0.25、900 → ×0.125`。

所以「直接对话 3.1」在实际数值上会变成 1.55（好感 300 时）、0.78（好感 600 时）——
基准值只是起点，不是恒定速度。

### 实测节奏

「轮」= 一次有效判定（15 分钟冷却后的一次）。给两个口径：

- **满负荷**：每天打满 96 次（每 15 分钟一次、不间断），是理论下限
- **每天 20 次**：比较接近真实群聊/私聊的频率

| 目标 | 旁听（满负荷） | 旁听（每天 20 次） | 直接对话（满负荷） | 直接对话（每天 20 次） |
|---|---|---|---|---|
| 熟悉（200） | 204 轮 / 3 天，**然后停** | 204 轮 / 11 天 | 82 轮 / 3 天 | 82 轮 / 5 天 |
| 亲近（500） | —（旁听封顶） | —（旁听封顶） | 304 轮 / 7 天 | 304 轮 / 16 天 |
| 老友（800） | —（旁听封顶） | —（旁听封顶） | 746 轮 / 12 天 | 746 轮 / 38 天 |

「直接对话」这一列在群里 @ 它、回复它，和私聊是同价同速的。

和旧版对比：群聊到「熟悉」是 2.3 → 3 天，基本持平；私聊到「老友」是 4.9 → 12 天，慢了一倍多。

**慢的原因不是倍率，是日上限**：直接对话一次 3.1，一天 26 次就撞到 `daily_gain_cap=80`，
后面 70 个窗口全被额度挡住。想快就把 `daily_gain_cap` 调大（比如 300，
满负荷就变成熟悉 1 天 / 亲近 4 天 / 老友 8 天），或者把两个基准同比例调大。

### 会记仇，也会忘

- **负好感**：被明确骂一句扣 10（群聊减半），下限 -100，掉到 0 以下进「不待见」。
  只认 20 字以内、带「你」的歧义词——「这游戏真垃圾」不算，「你就是个垃圾」才算。
  **不用 LLM 判定，零额外调用。**
- **自然衰减**：`1-(t/30)²`，7 天 -5%、半月 -25%、21 天 -49%、一月归零回落「陌生」。
  存基准值 + 基准时刻，读的时候按时间差算，不起定时任务——
  否则插件停机那几天不衰减，重启后数值会突然掉一大截。

### 老数据不用管

旧版本是「0.5 点/轮、60 秒窗口」再乘各层系数。升级时会自动 **×5** 换算一次，
带 `scaled_v2` 幂等标记，重启多少次都不会重复乘。

不重置衰减时钟（否则久没聊的人会被这次换算「续命」），负数不放大
（旧版本没有负向扣分，负值只可能是手动改的）。

## 🍚 喂食

好感除了聊天，还可以从 [「吃什么」](https://github.com/wjn1121/astrbot_plugin_chishenme) 插件喂出来。

群友发「吃什么」随机拿到一道菜，或者发「点菜 红烧肉」点中一道，都算一次投喂。「吃什么」在消息事件上挂一个字段，「群聊记忆」在回复发出去之前读到它，加好感，再把结果写进同一条回复：

```
今天建议吃：中餐硬菜 · 红烧肉 😋（投喂好感度 +2）
```

### 两种方式加成不同

| 方式 | 默认加成 | 理由 |
|------|:---:|------|
| 随机推荐 | +2 | 随手一问 |
| 点菜 | +5 | 明确说了要吃什么，比随手一问多花一点心思 |

两个数都能在面板调。设成 0 等于只保留另一种。

### 每人每天有次数上限

默认 2 次：随机一次、点菜一次。超出不加分，回复末尾会写「（今日投喂已到上限）」。

限次的理由：好感描述的是「这个人在群里处在什么位置」。如果反复发「吃什么」就能涨，它量的就是手速而不是关系。

### 不花钱

投喂走的是消息事件上的一个字段，两个插件之间没有网络请求，也不调模型。token 0。

### 投喂榜

面板「🍚 喂食」页按喂食次数排出榜单，显示每个人喂了多少次、最近喂的是什么。榜是给人看热闹的，不参与任何计算。

### 没装「吃什么」

这一页会一直空着，页面里有说明告诉你去哪装。

### 关掉

页面顶部有总开关。关掉之后「吃什么」照常出菜，只是不再涨好感。

## 🎚️ 风格强度与人格让位

三个旋钮，把「风格占多少」变成一个可调的量，而不是一直满额。

| 配置项 | 管什么 | 默认 |
|---|---|---|
| `style_strength` | 有人跟机器人说话时的风格强度 | `100` |
| `active_style_strength` | 机器人自己插话时的风格强度 | `60` |
| `style_override_threshold` | 强度严格大于多少才允许风格压过人格 | `100` |

强度不是只改措辞，**名额和措辞一起降**：

| 强度 | 注入名额 | 措辞 |
|---|---|---|
| `0` | 一条都不注入（纯人格） | — |
| `1–30` | 每类压到 1 条 | 极弱：「绝大多数回复都不要体现」 |
| `31–69` | 减半（`max_stable_inject` 5 → 3） | 「只在确实合适时体现」 |
| `70–99` | 四分之三（5 → 4） | 完整的使用要求 |
| `100` | 满额 | 完整的使用要求 |

只降措辞不降名额没用——模型嘴上说「仅供参考」，内容还是塞满 5 条，实际效果几乎不变。

### 让位是怎么算的

- 强度 **严格大于** 阈值时才让位，让位概率 = **强度值本身**。例如阈值 70 + 强度 100 → 每轮都按风格走；
  阈值 70 + 强度 85 → 85%
- 强度 **≤** 阈值时永远人格优先。所以**默认值（强度 100 + 阈值 100）等于开箱不让位**，
  行为和 1.2.0 一致：风格满额注入，但冲突时听人设
- 想让群风格压过人设，把 `style_override_threshold` 调到 100 以下，例如 70。
  面板「🎭 风格与人格」组下方会实时算出对应的让位概率，拖滑块就能看到，不用自己算
- 主动强度 60 默认也 ≤ 100，所以默认配置下主动插话不会推翻人格。这是故意的：
  插话本来就被嫌吵，再换一副嘴脸更糟

### 这不是真把人格删了

这是**指令层的优先级覆盖**。人格还在 system prompt 里，插件只是用明确措辞把「表达风格」
这一层的权重抢过来，并在声明里写明「身份、知识边界、安全约束仍然有效」。
所以实际服从率是倾向，不是保证——模型有时候照样按人设说话，这不是 bug。

为什么不真删人格：改 system prompt 会击穿 DeepSeek 的前缀缓存。命中缓存 ¥0.05/百万 token，
未命中 ¥1.5/百万，**30 倍差价**。为了几句风格把每轮输入都变成未命中价，不划算。

想要更硬的效果可以开 `style_override_deep`（默认关）：让位命中时把同一段声明再追加到
system prompt 末尾。代价是**该轮缓存必然失效**，输入按未命中价算。只在确实需要强效果时开。

## ✍️ 回复字数上限

被动和主动分开设，互不影响。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `reply_max_chars` | `0` | 被动回复字数上限。0 = 不限，与 1.2.0 行为一致 |
| `active_reply_max_chars` | `80` | 主动插话的字数上限。插话就该是路过接一句 |
| `reply_max_chars_hard` | `false` | 发送前硬截断，见下 |

**这是倾向，不是硬限制。** 设 80 实测常见 90–120 字，模型对字数的服从度就这样。
把它当硬限制去验收会以为是 bug，所以先写在这。

`reply_max_chars_hard` 开启后才在发出前按字数硬切，切到最近一个句末标点。**不建议开**：
会切坏 markdown 表格、链接、代码块和表情占位符，被切出来的是明显残句，比啰嗦更难看。
只在「宁可断也不能长」的场景手动开。

字数要求是单独一段，和风格注入分开发；所以 `style_strength` 调到 0（纯人格）时字数要求
照样生效。但 `inject_enabled` 关掉时两段一起停——它们挂在同一个钩子里。

## 🤣 表情包斗图

默认关闭（`sticker_enabled`）。图库是本地目录，挑图和发图都在本地完成：
判定是字符串匹配加一次掷骰，发图直接读文件，不进 prompt，也不改 system prompt。

### 图库从哪来

三个来源：

| 来源 | 怎么进 | 适合 |
|---|---|---|
| 面板上传 | 「🤣 表情包」页点上传，可多选 | 自己攒的一套 |
| 群里的图 | 发图时带一句 `/收图 笑 熊猫头` | 群友发的图最贴群口味 |
| bot 号的收藏 | `/收表情 全部` 或 `/收表情 50 笑` | 现成的、已经在用的那批 |

收藏表情走协议端的 `fetch_custom_face`，LLBot / NapCat 一般支持，取不到就报一句
「没拿到收藏表情」，不影响别的功能。按内容哈希去重，一次最多 200 张，
不带分类进「待整理」。支持 jpg / png / gif / webp，单张 5 MB，GIF 原样保存。

### 七档：按效果排，不按成本排

档位把七八项参数一起写进 `runtime.json`，写完每项仍能单独改；再点别的档位会整套覆盖。

| 档位 | 什么时候发 | 判断覆盖 | 冷却 / 日限 | 额外请求 |
|---|---|---|---|---|
| ⏸ 关闭 | 不发图，图库照常管理 | — | — / 0 | 0 |
| 🔤 字面 | 本地词表命中（哈哈、笑死、无语、破防…） | 关键词命中才判 | 120 秒 / 40 | 0 |
| 👥 跟风 | 同字面，另加跟图、队形、连发 | 命中或群友发图 | 90 秒 / 60 | 0 |
| 🔍 事后 | 回复发完后另调小模型猜情绪 | 15% 的轮次 | 90 秒 / 60 | 每轮约 26 token |
| 💡 轻度 | 模型在回复末尾自报 | 30% 的轮次 | 90 秒 / 60 | 每轮约 70 token |
| ⚖️ 标准 | 同上，判断更勤、冷却更短 | 60% 的轮次 | 60 秒 / 100 | 每轮约 70 token |
| 🔥 全开 | 每轮都问模型 | 100% 的轮次 | 45 秒 / 150 | 每轮约 70 token |

「判断覆盖」是省钱的那道闸：只在一部分轮次里告诉模型「这轮可以发表情」，其余轮次它不知道有这回事。
按每天 500 轮、单群算，事后档约一毛钱一个月，全开约四毛（按未命中价估，开了前缀缓存更低）。

**队形和连发**只在跟风及以上出现。队形是 30 秒内凑够 3 张图就跟着刷，不看概率也不看模式；
连发是发完一张再按跟图概率补一张同类的。两者都要过日限和冷却，`note_image` 凑够阈值就自清。

### 情绪从哪来

四种模式，面板里叫「情绪从哪来」：

| 模式 | 做法 | 成本 | 取舍 |
|---|---|---|---|
| `off` | 不发 | 0 | 只想管图库、不想让它发 |
| `keyword` | 本地词表命中，命中后掷骰 | 0 | 只认几个词，反讽和上下文读不懂 |
| `analyze` | 回复发完后另调一次小模型看正文 | 约 26 token/轮 | 不改回复格式，但看不到前文，反讽容易猜错 |
| `marker` | 让模型在回复末尾打 `<emo:笑>`，发送前剥掉 | 约 70 token/轮 | 最准：模型已经读完了上下文，顺手标一下 |

`marker` 是推荐档。标记在 `on_llm_response` 里剥掉，进历史和进学习材料的都是干净文本，
用户也看不到；写成 `[emo：笑]`、`【emo: 笑】` 也认。`analyze` 默认跟随当前会话的模型，也能单独指定。

### 回复生成完之后，先全库撞一次标签

`sticker_search_first` 默认开。回复生成完、准备配图时，拿正文撞图库里每张图的标签，
按 IDF 加权算分，最高分过阈值（默认 1.5）就发那张。

「笑」几十张图都带，命中几乎等于没命中；「熊猫头」只有三张带，撞上就该是那三张。
权重是 `log((图总数+1)/(带该标签的图数+1))+1`，和 BM25 的 IDF 是同一件事。
阈值 1.5 表示至少命中一个有点稀有的标签，或两个常见标签同时命中——只说一句「大肥鱼」不发。

这一步 0 成本：几百个标签做字符串包含是微秒级。撞不上就回到原模式，不额外发请求；出错也退回分类。

### 自动打标

上传完在面板点「识别」，或对全部未打标的图批量跑。模型返回图上文字、三到六个关键词和一句说明，
合并时只追加不覆盖手写标签——标歪一次不该把人工写的冲掉。

图上文字排第一：群友常直接把图上的话打出来当回复，这是检索里最值钱的信号。提示词要求用群里的口语
（「放毒」而不是「美食展示」），标签是拿去撞回复原文的，书面语等于白标。

一张约 ¥0.0007（关推理后；不关约五倍、慢三倍），200 张不到两毛。默认用 AstrBot 全局的
图片转述模型，也能单独指定。GIF 只取第一帧。

### 分类、标签、词云

分类是「桶」，标签是「钩子」：

- **桶**决定注入规则里列哪些名字。`marker` 模式下模型只能从有图的桶里选，空桶不列；
  桶的描述会拼进那段规则，模型才知道里面装什么
- **标签**决定检索能不能撞上，每张最多 16 个

内置十个桶：笑、无语、夸、哭、惊、摆烂、好、尴尬、爱、嫌弃，描述和六个关键词都能改；
自己新建上限 24 个，每个都会进注入规则，越多这段越长。

图库第一个是「全部」，顶部有标签词云，点一个就筛，搜索框一直留着。排序按上传时间、
修改时间、使用次数、名字。每张图能单独停用：留在库里，不参与检索和随机挑图。

### 什么时候不发

按顺序过这几道，任何一道不过就安静跳过：

| 闸 | 说明 |
|---|---|
| 总开关 / 模式 | 关着，或模式是 `off` |
| 图库为空 | 没图，或有图的桶全停用了 |
| 日限 | 所有群合计，默认 40～150，看档位；0 等于当天不发 |
| 冷却 | 同群两次发图的最小间隔，45～120 秒看档位 |
| 会话名单 | 在黑名单、用户黑名单里的不参与；填了白名单就只在白名单里生效 |
| 每日预算 | 超支只停「判断」，不停发图，退回纯关键词照发 |

## 🗣️ 主动回复

默认关闭。这是本插件唯一会主动开口的功能，插话的收益高度依赖群氛围，
默认开着只会让人以为机器人坏了。

开关有两层，是「与」的关系：**全局开关**在「🗣 主动回复」页顶部（`active_reply_enabled`）；
**按群开关**是页面下方列表里每个群的勾选。全局关掉时，
按群开着也不会说话。

### 三种触发方式

| 模式 | 怎么判 | 额外请求 |
|---|---|---|
| `probability` | 每个冷却窗口掷一次骰（默认 15%） | **0** |
| `rule` | 命中提问句式（有没有人知道/求推荐/怎么弄…）、自定义关键词、或冷场 5 分钟后有人开新话题 | **0** |
| `llm_judge` | 攒够 N 条消息问一次模型「现在接话自不自然」，只认整串 `REPLY` | 有，判定本身花钱 |

**骰子是按「冷却窗口」掷的，不是按消息掷的。** 这一点很关键：按消息掷的话，群越热闹
越容易被插话，正好和「别烦人」相反。窗口默认 30 分钟，一天最多 48 个窗口 × 15% ≈ 7 次期望值，
落在日限 8 以内。

### 概率不是固定的：先看群里热不热闹

`active_reply_chance` 现在只是**基准值**，真实概率每轮现算，全程本地、零请求：

```
p = 基准 × (1 − 0.7 × 群热度) × (1 + 0.4 × (1 − 群热度)) + 0.5 × 接话黏性
```

- **群热度**：最近 120 秒的消息数（10 条算满）。热闹时把概率压到三成，冷清时反而抬四成——
  安静时冒个泡是捧场，热闹时插话是噪音
- **接话黏性**：bot 刚说完话、3 分钟内有人接着讲（+0.65），或者有人抛问题
  （「有没有人知道」「求推荐」，+0.4），攒一个半衰期 5 分钟的分。
  bot 自己开口之后先降一截——「我说完了，轮到你们」
- **冷却期内也照样积累黏性**：不然「有人接话」这个信号等冷却过去就过期了
- 效果上限 0.85。日志里写 `probability 45%(基准70 热20 粘60)`，可以直接看这轮为什么高或低

### 五档预设（页面顶部一键切换）

| 档位 | 参与概率 | 冷却 | 日限 | 冷清阈值 | 静默时段 | 约 token/天 |
|---|---|---|---|---|---|---|
| 🛡 安静 | 0.05 | 3600s | 3 | 5 条 | 01:00–08:00 | 0.5 万 |
| ⚖️ 平衡 | 0.15 | 1800s | 8 | 3 条 | 01:00–08:00 | 1.2 万 |
| 🔥 活跃 | 0.35 | 600s | 20 | 2 条 | 02:00–07:00 | 3 万 |
| ⚡ 高频 | 0.55 | 300s | 40 | 2 条 | 02:00–07:00 | 6 万 |
| 🚀 常驻 | 0.80 | 180s | 70 | 1 条 | 03:00–07:00 | 10 万 |

一次改 5 个参数。这几个值是**互相咬合**的——只把概率拉高、冷却和日限不动，实际一句都不会多。
单独微调过其中任何一个，那一排会提示「已经不属于任何预设」。

**日限永远是最硬的闸门**：概率写 0.8 也只管「每次窗口敢不敢说」，一天说满 70 次就到顶，
而且群热闹时概率还会被压回三成——「常驻」不等于刷屏。

### 13 层闸门

每层都是本地判断，前 12 层零成本，只有 `llm_judge` 模式在第 13 层之后才发请求：

| # | 闸门 | 不过就 |
|---|---|---|
| 1 | 总开关 `active_reply_enabled` | 什么都不做 |
| 2 | 会话开关（`active.json`，管理员工具可改） | 该群永不插话 |
| 3 | 自己发的消息（含上一轮自己插的话） | 防自问自答 |
| 4 | 以 `/` 开头的指令 | 交给命令处理 |
| 5 | 没有文本（纯图片/表情/文件） | 跳过 |
| 6 | 这轮 @ 了机器人或被唤醒 | 交给正常回复链路 |
| 7 | 本轮已经有结果了 | 防重复回复 |
| 8 | 静默时段 | 默认 01:00–08:00，半夜刷群容易被踢 |
| 9 | 群太冷 | 最近 10 分钟少于 `active_reply_min_messages`（默认 3）条就不说话 |
| 10 | 日限 | 默认 8 次/群/天，按自然日（北京时间）重置 |
| 11 | 冷却 | 默认 1800 秒，命中与否都会推进 |
| 12 | 退避 | 连续 `active_reply_backoff_limit`（默认 3）次开口没人接才开始放大冷却：到第 3 次 ×2、第 4 次起 ×4 封顶；期间有人说话立刻清零 |
| 13 | 硬间隔 | 自己刚说完话 25 秒内不再掷骰子——防把冷却调到 60 秒后连发 |

### 默认值

| 配置项 | 默认 |
|---|---|
| `active_reply_cooldown_seconds` | `1800`（30 分钟） |
| `active_reply_chance` | `0.15` |
| `active_reply_daily_limit` | `8` |
| `active_reply_quiet_hours` | `01:00-08:00` |
| `active_reply_min_messages` | `3` |
| `active_reply_judge_stack` | `8`（仅 llm_judge） |
| `active_reply_backoff_limit` | `3` |

命中后会调 `should_call_llm(False)` 掐掉宿主原生的群聊回复，避免同一句话回两遍。

> ⚠️ **必须检查的一件事**：如果 AstrBot 那边开了「群聊无需 @ 也回复」，务必先关掉。
> 插件只是掐掉当前这条消息的原生回复，AstrBot 自己的策略仍然可能让它再回一遍，结果就是双回复。

> ⚠️ **已知限制（不是 bug）**：主动回复的「群太冷」判断依赖插件的消息缓冲，而这个缓冲受
> **学习开关**控制（`enabled` + 白名单/黑名单 + 会话级学习开关）。所以**关掉某个群的学习之后，
> 那个群不会有主动回复**。想要插话又不想学习，目前做不到。

## 🔍 联网搜索接管

开关有两层：**总开关** `web_search_enabled`（默认关，面板「🌐 联网搜索」页第一项），
和下面的**接管模式**。总开关关着时，连搜索工具都不会挂给模型——它不知道有这回事，
也不会浪费 token 去试着搜。从旧版本升级的用户只有 `web_search_mode`，记得把总开关也打开。

### 三种模式

| 模式 | 行为 | 能按群限次吗 |
|---|---|---|
| `plugin`（默认） | 插件自己挂搜索工具，覆盖 AstrBot 内置的同名工具 | 能，每群每天独立配额 |
| `inherit` | 完全沿用 AstrBot 全局设置，插件不管 | 不能，插件既不统计也不限次 |
| `off` | 就算 AstrBot 全局开着，也把搜索工具全摘掉 | — |

`plugin` 模式下如果配不到 key（key 为空、或选了不支持的服务商），插件会把**内置搜索工具一起摘掉**。
这是故意的：留着的后果是模型绕过配额照搜，每日上限就成了摆设——此时表现为「完全不会搜」。

### 四家服务商

| provider | 单价 | 说明 |
|---|---|---|
| `deepseek`（默认） | ¥0.005/次 | 复用你的模型 key，国内直连，失败/无结果不计费 |
| `tavily` | 有免费额度 | 免费 1000 次/月，国内可直连 |
| `bocha` | 按套餐 | 国内可直连 |
| `brave` | 有免费额度 | 需要梯子 |

### DeepSeek 搜索的几个事实

- 官方 2026-10-17 上线 Search / Fetch API，端点是 `https://api.deepseek.com/v1/tools/search`
- 和模型 API **用同一个 key**，所以「配 key」这一步多数人不用做
- **¥5 / 1000 次成功请求 = ¥0.005/次**；返回失败、搜不到结果、超时都不计费
- 2026-11-01 起正式收费（此前通过 Agent 框架调用的那段是免费的）
- **模型不会自己搜**：这是独立 REST 接口，不在 `chat/completions` 的 tools 里。
  必须由 AstrBot 或插件把工具挂给模型，模型才会通过 tool_call 触发。这也是为什么
  插件能接管——挂不挂、挂谁的，是请求前那一刻决定的

### 配额怎么卡

- `web_search_daily_limit` 默认 **20 次/群/天**，跨群独立，按日期天然归零
- **两层拦截**：挂载前当天已满就**根本不挂工具**，模型连入口都看不到，不会反复尝试；
  调用前再判一次，防一轮里超发
- `web_search_max_per_turn` 默认 2，防模型连环搜把当天配额一次烧完
- 只有真的拿到非空结果才扣次数，请求失败不冤枉你
- **主动回复一律不搜索**（三种模式通吃）。为一句插话等 8 秒不值得，而且 AstrBot 不知道
  这轮是插话，全局的搜索工具得插件主动摘掉

### key 只存一处

`web_search_reuse_global_key` 默认开：插件 key 留空时，自动读 AstrBot 全局配置里同一家的 key。
好处是 key 只存一处，**不会在 `runtime.json` 里留明文**。反之，如果你在插件配置里填了 key，
它会明文落盘到 `runtime.json`——介意就别填，靠复用。

20 次/群/天 ≈ **¥0.15/群/天**；10 个群全打满 ≈ **¥1.5/天 ≈ ¥45/月**。

> 要么就继续用 DeepSeek。

## 💸 消耗统计与花费上限

账单在**插件自己的数据目录**里：`AstrBot/data/plugin_data/astrbot_plugin_qunliaojiyi/token/YYYY-MM-DD.json`。
放在这里而不是 data 顶层，是为了让用户迁移数据、审计存储时不会漏掉这份账单（AstrBot 市场的上架要求）。
保留 400 天（`token_stats_keep_days`），超出的自动删——面板要按周、月、年往回看，
留 7 天就只剩最近几天有数。一天一个几 KB 的小文件。

> **从旧版本升级**：老账单在 `AstrBot/data/qunliao_token/`，插件仍能读到，只是不再往里写。
> 这一天只要再记一笔，账就会合并着写进新位置；旧文件留在原地，确认没问题后可以自己删掉。

**只存数字，不存任何消息内容。** 文件被看到也不会泄露聊天。

统计分两块，口径不一样：

| 来源 | 精确度 | 内容 |
|---|---|---|
| 插件自己发起的请求 | 精确 | 学习次数与 token、`llm_judge` 判定、画像重写、表情打标、搜索次数 |
| 每轮回复 | **下限** | `on_llm_response` 里拿到的 usage |

**全机数字是下限**：多轮工具调用中间的请求会漏计（AstrBot 只在最终响应上报 usage），
显示的金额只会比真实账单少。

每个日文件还按**小时**分了 24 个桶，「今日调用分布」那张图就是读它画的。分时只记金额、
调用次数、token 三段和搜索次数，不记具体请求——省磁盘，也不留隐私。

计价默认按 DeepSeek 牌价折算：缓存命中输入 ¥0.05/百万、未命中 ¥1.5/百万、输出 ¥4.5/百万。
峰谷按**逐笔**算——工作日 09:00–12:00、14:00–18:00（北京时间）按 2 倍，周末全天空闲价。
节假日不单独处理，会被当成工作日，所以会略微高估。

价格全是配置项（`token_price_*`），DeepSeek 调价了自己改，不用等插件更新。

### 面板怎么看

「💸 Token 消费」页分三层：

| 位置 | 看什么 |
|---|---|
| 顶部预算条 | 今天花了多少、限额多少、还剩多少；超了可以当天放开 |
| 今日构成 | 学习 / 回复 / 主动插话 / 画像 / 打标 / 搜索分开，能看出钱花在「你问它」还是「它自己开口」 |
| 趋势与累计 | 近 7 天 / 近 30 天切换，下面是累计：总金额、总调用、总搜索、记账天数、各来源占比 |

切到 30 天时横轴按天抽稀、柱子变细，卡片高度不变。累计面板只累加各天文件里已写的金额，
不重算 token——历史牌价可能不同，重算等于改旧账。

### 每日花费上限

默认关闭（`daily_budget_enabled`），金额默认 2 元（`daily_budget_yuan`）。
开了之后，当天累计花费到线就自动把还会产生新请求的功能收一收：

| 功能 | 超支后 |
|---|---|
| 学习（后台提炼） | 停 |
| 主动回复 | 停 |
| 画像生成 / 重写 | 停 |
| 联网搜索 | 工具不挂给模型，模型不知道有这回事 |
| 表情包 | 退回纯关键词：还发图，但不再花钱问「该不该发」 |
| 消息收集、标签写入、本地发图 | 照常，这些不花 token |

**跨零点自动恢复**：用量本来就是一天一个文件，过了零点读的是新文件，自然归零，
不用定时器也不用重启。超支期间消息照常收集，只是不提炼，恢复后不会断一截。

**当天想破例**：预算条旁边有「今天先放开」，只记一个日期，不动任何配置，重启后也算数；
过零点自动失效。点「恢复限制」立刻收回。

`daily_budget_yuan` 改成 0 等于关掉。金额按面板估算值算（受牌价影响，不是真实账单）。

## 🛡️ 管理员与清空拆分

管理员 = AstrBot 全局 `admins_id` + 插件配置里的 `admin_extra_users`。

`admin_tool_enabled` 默认关。开启后管理员在群里直接说话就能查状态、改参数、加/删记忆、
触发学习、清数据、开关主动回复，不用打命令。

**非管理员群里这个工具根本不会挂给模型**，不是挂上去再在调用时拒绝——列表里压根没有它，
别人看不到也没法用 prompt 注入诱导它。挂载时判一次、`call()` 里再判一次，防配置热更新后判断过期。

能改的项由 `core/settings.py` 的 `RUNTIME_KEYS` 白名单决定（面板上那些项都在名单里，名单里还有一些不直接露在页面上的字段），
写入 `runtime.json`，和面板同一套机制，能一键恢复配置值。不在名单里的配置项只能去插件配置页改。

### 清空拆成五个 scope

| 入口 | scope | 清掉什么 | 要确认吗 |
|---|---|---|---|
| `/清空风格` | `learned` | 学习产出（稳定 + 场景化 + 学习记录） | 否 |
| `/清空记忆` | `manual` | 面板手动记忆 | 否，但不可恢复 |
| `/清空记录` | `history` | 待学习消息缓冲 | 否 |
| 面板「清空全部」/ 工具 `clear(all)` | `all` | 上面三项 + 主动回复状态 | 面板有确认框 |
| `/清空风格 全部` → `/确认清空` | `all` | 同上 | 是，60 秒内确认 |

`learned` 不再连带清待学习消息：清掉学习产出后往往想留着消息重新学一遍。

置顶（`pins.json`）不在这五个 scope 里：它只是面板的显示偏好，不是记忆数据，
清空之后你还想按原来的顺序找到那几个群。

### 💰 哪些调整会改变 token 消耗

配置页里每一项的提示都标了影响方向，这里汇总成一张表：

**减少消耗**

| 调整 | 效果 |
|---|---|
| 关闭 `enabled` | 归零：不收集、不学习、不注入 |
| 关闭 `inject_enabled` | 每条回复少带几十字风格文本，学习能力保留 |
| `learn_increment_messages` 调大 | 30 → 60，学习次数大致减半，代价是风格更新变慢 |
| `learn_min_interval` 调大 | 1800 → 3600，刷屏群不会连着学 |
| `min_history_for_analysis` 调大 | 太冷清的会话不再触发兜底学习，但样本也更少 |
| `trait_max_total` 调小 | 库小了，注入候选少、命中率降，但不影响每次 prompt 长度 |
| 关闭 `learn_self_check` | 每个群每次学习少一次小请求（约 600 token），代价是容易收进一次性玩梗 |
| `max_messages_per_learn` 调小 | 80 → 40，单次学习 prompt 大致减半 |
| `max_stable_traits` / `max_situational_traits` 调小 | 学习时带入的「已有特征」变短 |
| 关闭 `enable_emb_selection` | 完全不再发 embedding 请求，纯靠触发词和关键词 |
| 保持 `enable_trigger_matching` 开启 | 命中触发词就跳过向量请求，这是省钱关键 |
| `analysis_provider_id` 换成便宜模型 | 学习任务不需要强模型，flash 比 pro 便宜一个量级 |
| `style_strength` / `active_style_strength` 调低 | 名额和措辞一起降，强度 0 时风格一个字都不注入 |
| `reply_max_chars` / `active_reply_max_chars` 设小 | 回复变短，输出 token 是单价最高的那一段 |
| 主动回复保持关闭 | 这块本来就不产生请求 |
| `web_search_daily_limit` 调小 | 按次数计费，压到几本就是直接省钱 |
| `profile_enabled` 关闭 | 每轮少一段画像（陌生 120 字到主人 800 字） |
| `profile_daily_cap` 调小 | 直接压低每天的重写次数上限 |
| `fact_shallow_days` / `deep` / `core` 调小 | 记忆死得更快，每轮可注入的条目变少（省得不多，主要是记忆质量） |
| `bond.tiered_memory` 关闭 | 回到固定上限，陌生人也会按满额注入 |

**增加消耗**

| 调整 | 效果 |
|---|---|
| `max_stable_inject` 调大 | 每条回复多带几条学习风格，每条 10–30 字 |
| `max_manual_inject` 调大 | 每条回复多带几条手动记忆（手动记忆是常态注入，不是按需匹配） |
| `max_situational_inject` 调大 | 命中时多带几条梗，每条 5–20 字 |
| 开启 `enable_cross_group` | 每条回复都额外带上其他群的风格 |
| `situational_similarity_threshold` 调低 | 更容易注入，token 略增且容易乱接梗 |
| 开启 `active_reply_enabled` | 一天最多 `active_reply_daily_limit` 次主动请求，每次约 1500 token |
| `active_reply_mode` 用 `llm_judge` | 判定本身也发请求，200 条/天的群约 25 次/天 |
| `web_search_max_results` 调大 | 5 条约 1200 token，10 条大致翻倍 |
| 开启 `web_search_need_content` | 每条结果带整页正文，成本翻十倍以上 |
| 开启 `style_override_deep` | 该轮输入按未命中价算，差 30 倍 |
| 开启 `admin_tool_enabled` | 多一个工具定义，约 200 token/轮 |
| `profile_enabled` 开启且关系在涨 | 画像字数随档位变多，主人档最多 800 字 ≈ 500 token/轮，实际多在 300~500 字 |
| `bond.tiered_memory` 开启 | 关系越近，注入的关系段和事实条数越多（主人档约 +97%） |
| `facts.enabled` 开启 | 每轮多 1~10 条事实 / 80~500 字 |
| `facts.inject_summary` 关闭 | 浅层不再按类合并，10 条会变成 10 行 |

**不影响 token**：`embedding_timeout_seconds`（只影响延迟）、`history_limit_per_session`（只影响内存，但会影响主动回复的冷清判断）、`debug_mode`（只影响日志）、`startup_learn_delay_seconds`（只影响首轮时间）、`style_override_threshold`（只改让位概率，不改文本量）、`token_price_*`（只影响金额估算）、`bond.growth_per_turn` / `bond.group_passive_gain` / `bond.group_gain_cap` / `bond.growth_curve_scale` / `bond.daily_gain_cap`（只改好感涨多快）、`facts.max_per_user`（只管存几条，每轮注入的是配额）、`profile_min_facts`（只决定什么时候写第一版）。

### 七、累积链路

*面板位置：⚙️ 参数 › 「运行与学习」。`style_group_render`、`review_require_manual` 只在配置页*

这组控制「学到的风格怎么长大」。默认值按群聊量级调过，一般不用动。

链路设计参考 **MaiBot 的 Expression 表**：`situation`（什么时候说）+ `style`（怎么说）双段、
以出现次数当权重、写入用累加而不是整表覆盖、召回按权重加权。这里用已有的 `context` / `content`
两个字段承载，没有另建数据结构，所以旧数据不用迁移就进得了新链路。

| 配置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `learn_mode` | 字符串 | `accumulate` | `accumulate` = 增量累积；`replace` = 1.3.x 的整表重写（回退用） |
| `learn_increment_messages` | 整数 | `30` | 攒够多少条新消息就学一次 |
| `learn_min_interval` | 整数 | `1800` | 两次学习的最小间隔（秒），防止刷屏时烧钱 |
| `learn_candidate_max` | 整数 | `12` | 单次提炼的候选上限（只是候选，不是库存上限） |
| `learn_require_evidence` | 布尔 | `true` | 候选必须带本轮原文证据，对不上直接丢弃 |
| `learn_self_check` | 布尔 | `true` | 入库前再问一次模型「这是长期习惯还是一次性玩梗」 |
| `trait_activate_count` | 整数 | `2` | 新特征要跨几轮被观察到才进注入 |
| `trait_inject_min_count` | 整数 | `2` | 进注入所需的最低有效权重（2 = 被观察到 2 次） |
| `trait_decay_days_full` | 整数 | `30` | 多久不出现权重见底（二次曲线，只影响排序不改存储值） |
| `trait_archive_days` | 整数 | `30` | 多久没活跃可归档（归档不删数据，可恢复） |
| `trait_max_total` | 整数 | `150` | 每会话在库上限，超出按有效权重从低到高归档。注入每轮只用 5 条，多出来的只会拖长学习 prompt 和面板 |
| `style_group_render` | 布尔 | `false` | 注入时按语气/节奏/互动/话题/黑话分组渲染 |
| `review_require_manual` | 布尔 | `false` | 新条目必须人工批准才生效 |

13 项都在热调白名单里，面板上能改 11 项；`style_group_render` 和 `review_require_manual` 要去配置页。

### 八、关系状态

*面板位置：这几项是 `bond.*` 嵌套结构，只在插件配置页；面板只能看和手调每个人的好感与称呼*

| 配置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `bond.enabled` | 布尔 | `false` | 总开关。这是插件第一次「对人下判断」，所以默认不开 |

## 🧾 成本结构

这一章回答两个问题：默认配置到底花不花钱、开了下面这些可选项会变成什么量级。

### 默认配置为什么几乎不花钱

以下是**默认配置**（学习 + 被动注入开着，主动回复关、联网搜索没人触发）的口径：

| 环节 | 本插件 | 逐条判断的实现 |
|------|--------|----------------|
| 回复时选风格 | 读本地 JSON，**0 网络请求** | 每条消息调一次 LLM |
| 学习时机 | 攒够 30 条新消息增量一次（最小间隔 30 分钟，6 小时兜底） | 每 10 分钟多任务轮询 |
| 最小触发量 | 攒够 30 条才发请求 | 门槛更低、任务更多 |
| 每次发多少 | 只发新攒的那部分，不发整包 | 换话题就重发全部上下文 |
| 失败处理 | 不自动重试，等下一轮 | 会重发整包 |
| 场景化匹配 | 触发词本地命中，命中即不请求向量 | 每次请求 embedding |
| 手动记忆 | 面板手写，存本地 JSON，注入时直接合并，**0 请求** | 每轮让 LLM 从对话里重新推断一遍 |
| 风格强度 | 掷骰、分档全是本地计算，**0 请求** | — |
| 表情包（默认关） | 关着时一张不发；开关键词档也是本地字符串命中，**0 请求** | 每张图都过一次视觉模型 |

学习请求数跟着群活跃度走，不跟时间走：每天 150 条的群大约 5 次，再热闹也被「最小间隔 30 分钟」
压住上限。手动记忆无论加多少条都不产生请求。

### 可选功能会多花钱的几处

都是可选项，不开就不花钱。但开了之后成本结构会变，所以给具体数字，不给「很便宜」这种形容词。

| 来源 | 口径 | 量级 |
|---|---|---|
| 主动回复（probability / rule） | 每次约 1500 token，日限 8 次/群 | ≈1.2 万 token/天/群 |
| 主动回复（llm_judge） | 再加判定：每 8 条消息判一次，群里 200 条/天 ≈ 25 次判定 | 判定额外 ≈1.5 万 token/天/群，**比插话本身还贵** |
| 联网搜索（plugin 模式） | 单次 ≈¥0.0075（搜索 ¥0.005 + 约 1200 token 上下文 + 多说几句） | 20 次/群/天 ≈ ¥0.15/群/天；10 群打满 ≈ ¥1.5/天 ≈ ¥45/月 |
| 入库自检（`learn_self_check`，默认开） | 每个群每次学习多问一次「这是长期习惯还是一次性玩梗」 | 每次约 600 token，相对整轮提炼只是零头 |
| 事实抽取 | **并进现有学习请求**，不额外发调用，只让 prompt 多约 400 字 | 每次学习多 ≈600 token，**没有独立请求** |
| 个人画像重写 | 每人一次约 800 token，每天最多 6 人 | ≈5000 token/天，**全天封顶** |
| 关系判定 | 纯本地算，不调模型 | **0**，连 embedding 都不发 |
| 表情包·模型自报（`marker`） | 每轮约 70 token，只在 `sticker_mood_rate` 比例的轮次里问 | 30% ≈ 1 万 token/天/群；100% ≈ 3.5 万 |
| 表情包·事后分析（`analyze`） | 每轮约 26 token，独立一次小请求 | 15% ≈ 2000 token/天/群，但多出的调用次数要算进去 |
| 表情包·标签检索 | 拿回复正文撞本地标签表，不发请求 | **0** |
| 表情包·自动打标 | 一张一次视觉调用，约 ¥0.0007（关推理后） | 200 张 ≈ 一毛四；关推理失败时约五倍 |
| 风格强度 | 强度 100 满额注入 vs 强度 0 完全不注入，差值就是每轮几十到一百多字 | 高强度多花，低强度省 |
| `style_override_deep` | 命中轮次的 system prompt 变了，输入按未命中价（¥1.5/百万 vs ¥0.05/百万） | 单轮影响小，天天命中就不小 |

几条省钱的判断标准：

- **想开主动回复，先用 `probability` 或 `rule`**。两种模式判定零请求，只有真开口那一次花钱；
  `llm_judge` 是唯一「先花钱问该不该说，再花钱说」的模式
- **日限别往 20 以上调**。QQ 对高频主动发言有风控风险，而且很招人烦
- `web_search_max_per_turn`（单轮）和 `web_search_daily_limit`（全天）是两道闸：单轮上限管
  「一次对话最多搜几次」，日限管「这个群一天总共几次」。两个都往大调才会叠加烧钱
- 不确定要不要搜索提示语（`web_search_hint`）就先留空，它会让模型搜得更勤，而搜索按次计费
- **画像的开销是可预算的**：`profile_daily_cap`（默认 6 人/天）直接钉住上限，
  跟群里人数无关。人多的大群想省就压到 2~3；反正只有「新增 ≥2 条事实」的人才会被重写
- **事实存得多不等于花得多**：注入配额（1~10 条 / 80~500 字）是封顶的，
  存储上限只决定「记得住多久」，不决定「每轮发多少」

### 各项成本的调节点

上面每一处开销都有对应的配置项，能压到什么程度列在最后一列：

| 成本项 | 对应参数 | 可压到的范围 |
|---|---|---|
| 主动回复（唯一会主动开口的功能） | 顶部五档预设：安静 / 平衡 / 活跃 / 高频 / 常驻 | 0.5 万 ~ 10 万 token/天；关掉就是 0 |
| 每轮带多少记忆进 prompt | `bond.inject_max_chars`、`facts.max_inject`、`facts.inject_max_chars` | 条数与字数双上限，还随好感自动分档（陌生 2 条 / 80 字） |
| 一个人的画像多厚 | 档位默认（120~800 字）+ 单人覆盖 | 单人设成 0 = 这个人的画像既不生成也不注入 |
| 记忆活多久 | `fact_shallow_days` / `fact_deep_days` / `fact_core_days` | 调小 → 归档更快 → 可注入的候选更少 |
| 一次学习喂多少 | 攒够 30 条才学；单条截 200 字、整次预算 4000 字符 | **与消息量脱钩**，群再热闹也不会无限涨 |
| 画像多久重写 | `profile_rewrite_hours` / `profile_daily_cap` | 默认每天最多 6 人 ≈ 5000 token，全天封顶 |
| 表情包怎么判 | 七档预设 → 再单改 `sticker_mood_mode` / `sticker_mood_rate` / `sticker_daily_limit` | 关键词档 0；模型自报按比例，日限封顶 |
| 打标花多少 | 只在手动点「识别」时才花，自动打标默认不开 | 一张 ¥0.0007，图库一次性跑完就结束 |

各项都有硬上限，最坏情况可以算：关掉主动回复、画像上限设成 0、遗忘天数调成 7 天，
剩下的只有每次学习那一个请求，和每轮几百 token 的注入（后者按缓存命中价计）。

面板上的参数都标了「默认 X」和 token 影响箭头（`↑↑↑` / `↑↑` / `↑` / `↓` / `token 0`），
改完下一轮生效，不需要重启。

### 注入一次多少钱

主人档把上限拉满：关系段 300 字 + 事实 500 字 + 画像 800 字 ≈ 1600 字，约 1100 token。
按缓存命中价（0.05 元/百万）算，一轮约 0.00006 元；一天 500 轮约 0.03 元（三分钱），
高峰时段价格翻倍，约 0.06 元。

这几个数随 `token_price_*` 变动，改牌价后重算即可。

## 🧬 人格档案

学习库里的特征是一条条零散的观察，人格档案把它们整理成**一份能直接读的文件**。

### 文件在哪

```
AstrBot/data/plugin_data/astrbot_plugin_qunliaojiyi/persona/
├── bot1_GroupMessage_1038882918.md
├── bot1_GroupMessage_165465552.md
└── bot1_FriendMessage_8848.md
```

放在**插件自己的数据目录**里，和 `token/`（消耗统计）平级。这是 AstrBot 市场的上架要求——
持久化数据必须在 `plugin_data/<插件名>/` 内，否则用户换机器迁移、审计存储时会漏掉它。
插件升级、从市场重装都碰不到这个目录，你也可以直接用文件管理器打开、备份、丢进 Git。

> **从旧版本升级**：老档案在 `AstrBot/data/qunliao_persona/`，插件仍能读到（面板里那份会标「来自旧位置」）。
> 对它点一次「重新生成」或保存人工段，内容就会落到新目录，旧文件留在原地不动。

### 长什么样

```markdown
# 群 1038882918 · 人格档案

> 本文件由「群聊记忆」插件维护，可以直接编辑，但只有最后一段属于你。
> 自动生成于 2026-10-31 22:45，取自学习库中已生效的 21 条特征（稳定 10 / 场景 11）。

<!-- AUTO:BEGIN 以下内容由插件自动生成，学习或审核后重写；改这里会被覆盖 -->

## 语气
- 句末常带喵、qwq、唉唉等语气词卖萌起哄

## 节奏
- 短句碎发连发，一句一气泡

## 场景反应
- 当有人嘲讽 bot 时：回嘴但不过分

<!-- AUTO:END -->

<!-- MANUAL:BEGIN 以下内容来自人工补充，插件永远不会修改这一段 -->

群友管句尾的「呢」叫阴阳怪气，别用。

<!-- MANUAL:END -->
```

### 两段的分工

| 段 | 谁维护 | 什么时候变 | 手改会怎样 |
|---|---|---|---|
| **自动生成** | 插件 | 每次学习完成、每次批准/否决/归档后重写 | 会被覆盖 |
| **人工补充** | 你 | 只在你在面板里点保存时 | 永远保留 |

**自动段只收「已生效」的特征**：待审的、被否决的、已归档的都不进来。人格档案是这个群
**已经确认的样子**，不是还在观察的候选池。所以批准一条特征，人格档案下一次就会长出一条；
否决一条，它就消失。

物理隔离而不是「合并后一起写」：程序只替换 AUTO 两个标记之间的内容，人工段原样保留。
这比任何「保留用户修改」的启发式规则都可靠——只要程序不碰那一段，你写的东西就不可能被
下一轮学习冲掉。

> 标记被手改坏了也不丢内容：解析不出 MANUAL 段时，会把 AUTO 段之后的全部内容当作人工段
> 保留，最多多几个标记残片。**不会**让面板显示成空白（那样下一次保存就真的把手写内容覆盖了）。

### 怎么用

1. **看一眼**：面板「🧬 人格档案」页，左边选群，右边自动段和人工段分开显示。
2. **补充**：在「人工补充」框里写，点保存。写的是这个群特有的规矩、禁区、称呼习惯。
3. **拿走**：点「复制全文」，粘到 AstrBot 的「人格设定」里；或者「下载 .md」存档。

> ⚠️ 人格档案**不会自动注入对话**。真正影响回复的仍然是「学习库 → 风格注入」那条链路，
> 人格档案是给人看的汇总件和可移植的产物。要让它生效，得手动复制到 AstrBot 人设里——
> 那样就由 AstrBot 的人格系统接管，插件不再插手，也不会破坏前缀缓存。

### 什么时候不会自动生成

- 这个群还没学到任何东西（学习库是空的）
- 特征全是待审状态，一条都没批准
- 你手动删了文件——下次学习或批准时会重新生成

面板里点「重新生成」可以立刻按当前特征重写自动段，人工段不受影响。

## 💾 数据说明

数据目录：`AstrBot/data/plugin_data/astrbot_plugin_qunliaojiyi/`

| 文件 | 内容 |
|------|------|
| `universal.json` | 每个会话**自动学到**的特征（默认增量累积；`learn_mode=replace` 时整表替换） |
| `manual_traits.json` | 每个会话**手动添加**的记忆（学习流程不读不写，只在注入时合并） |
| `chat_history.json` | 待学习的聊天缓冲（含原文，学完即清空） |
| `learn_state.json` | 每会话学习元信息与最近 20 次记录，删掉可自动重建 |
| `metrics.json` | 全局累计统计 |
| `overrides.json` | 会话级开关（单独关闭的群） |
| `active.json` | 主动回复的会话状态（今天说了几次、下次评估时间、连续无人接话次数） |
| `pins.json` | 面板里置顶的群号 / QQ 号及其顺序，纯显示偏好，清空记忆不会清它 |
| `bonds.json` | **关系**：按 QQ 号的好感、轮次、称呼、衰减基准 |
| `facts.json` | **事实**：按 QQ 号的事实明细，含档位、熟练度、状态、说法变体 |
| `profiles.json` | **个人画像**：每人一段概述 + 人工补充段 + 单人手调的字数上限 |
| `runtime.json` | 面板/管理员工具热调的参数覆盖 |
| `sticker_labels.json` | **表情包分类表**：每个桶的名字、描述、本地关键词，用户改了就以它为准 |
| `sticker_index.json` | **每张图的元数据**：标签、用过几次、上次用、停用状态、上传时间 |
| `sticker_stats.json` | 发图记账：每天每个分类发了几张，用来卡日限 |
| `budget.json` | 每日花费上限的「今天先放开」记录，只存日期 |

表情包图片本体、消耗统计和人格档案各自一个子目录：

| 路径 | 内容 |
|------|------|
| `stickers/<分类key>/<文件名>` | 图库本体。目录名用英文，中文名在个别系统上会因编码打不开 |
| `token/YYYY-MM-DD.json` | 每天一个文件，存 token 数、金额与 24 小时分布，保留 400 天 |
| `persona/<会话>.md` | 每个群 / 私聊一份人格档案，见上文「人格档案」 |

`sticker_index.json` 的键是 `分类key/文件名`，和目录结构一一对应，删了图或挪了分类都会跟着更新。
标签最多 16 个，`disabled` 为真的图留在库里但不参与检索和随机挑图。

> **从旧版本升级的用户**：这两份数据原先在 `AstrBot/data/qunliao_token/` 与
> `AstrBot/data/qunliao_persona/`（data 顶层，不符合市场的持久化目录要求）。现在写入一律走
> 上面两个子目录，旧位置仍然只读兼容——读得到、不会再往里写，确认新位置正常后可以把旧目录删掉。

> 📌 特征分两个文件存不是多余的设计：自动学习是「整表替换」语义，如果手动加的
> 记忆混在同一张表里，下一轮提炼没复述到就会被静默删掉。物理分开后，学习不可能
> 覆盖手动记忆，两者也没法互相挤占存储上限。

`manual_traits.json` 和 `universal.json` **结构完全同构**，都是
`{unified_msg_origin: [trait, ...]}`，备份、迁移、手写脚本都省事：

```json
{
  "bot1:GroupMessage:1038882918": [
    {
      "content": "禁用谐音梗和网络流行语",
      "category": "stable",
      "context": "",
      "triggers": [],
      "confirmed_rounds": 0,
      "proficiency": 60,
      "last_seen": 1793000000.0,
      "last_updated": 1793000000.0
    }
  ]
}
```

手动条目的 `confirmed_rounds` 恒为 0（它表示「学习确认过几轮」，人工写的不该有计数），
`source` 字段在读取时才补，不落盘。

**这三个文件**是「一人一条」或「一人一桶」的形状，和特征的「会话 → 列表」不同：

```json
// facts.json：桶键是纯 QQ 号，不掺会话
{
  "123456789": [
    {
      "id": 1,
      "text": "养了一只橘猫，取名叫团子",
      "kind": "fact",
      "status": "active",
      "tier": "core",
      "seen": 4,
      "importance": 5,
      "last_seen": 1793000000.0,
      "variants": ["家里养了只橘猫"]
    }
  ]
}

// profiles.json：一人一条，chars 是面板上手调的字数（0 = 跟档位走）
{
  "123456789": {
    "text": "他是群里折腾 bot 的技术型角色，长期混二次元手游……",
    "manual": "他是我室友，别调侃学历",
    "updated_at": 1793000000.0,
    "basis": 12,
    "chars": 0
  }
}
```

> 📌 **为什么「置顶」存在 `pins.json` 而不是事实记录里**：「这个人我想一直看着」是展示偏好，
> 不是记忆数据。存进事实里的话，点一下「清空这人」就把这个偏好一起带走了。

> ⚠️ `chat_history.json` 会保留未学习的聊天原文，`learn_state.json` 含群号，
> `facts.json` / `profiles.json` 会保留「关于某个人的事」——这三类的敏感程度比风格特征高得多。
> 都在本地，插件不会外传；备份和归档时建议加密。

历史数据建议**单独存放在仓库之外**，不要在插件目录里堆积。需要导入时再复制到
`AstrBot/data/plugins/astrbot_plugin_qunliaojiyi/backup/<目录名>/`，导入完即可移除。

## 🔌 Web 接口

面板自己就是这几个接口的客户端，二次开发（自建看板、接监控、批量灌数据）可以直接调。
路由注册在 AstrBot 的插件 Web API 命名空间下，前缀为插件名 `astrbot_plugin_qunliaojiyi`：

| 方法 | 路由 | 说明 |
|------|------|------|
| `GET` | `/status` | 全局统计、会话列表（支持 `query` / `sort` / `page`）、注入名额、已知平台前缀 |
| `POST` | `/manage` | 全部写操作，靠 body 里的 `action` 区分 |
| `POST` | `/preview` | 传会话 + 一句话，返回这轮实际会注入的文本 |
| `POST` | `/import` | 导入 `backup/<目录>/` 下的备份，`mode=merge` / `replace` |
| `GET` | `/export` | 导出全部数据为 JSON（含关系、事实、画像） |
| `GET` | `/traits` | 学习库：带 `session_id` 看单个群，不带就跨群汇总并附 `groups` 分组 |
| `POST` | `/review` | 特征审核：`approve` / `reject` / `archive` / `restore` / `pin` / `unpin` / `approve_all` / `delete_trait` / `drop_session` / `purge_inactive` / `learn_on` / `learn_off` |
| `GET` | `/persona` | 人格档案：不带 `session_id` 返回概览，带则返回该群全文（含自动段与人工段） |
| `GET` | `/facts` | **事实记忆**：一人一行，含档位、熟练度、保留度、画像快照 |
| `POST` | `/facts` | **事实写操作**：`pin` / `pin_user` / `set_tier` / `prune` / `prune_all` / `prune_owner` / `merge` / `save_profile` / `rewrite_profile` / `set_profile_chars` / `delete` / `clear` |
| `GET` | `/bond` | **关系**：好感、档位、称呼、轮次、衰减后保留率 |
| `GET` | `/feed` | **喂食**：投喂榜（谁喂过、几次、最近一道菜）+ 当前加成与每日上限 |
| `GET` | `/active` | **主动回复**：按群开关状态、今日已回次数与上限 |
| `GET` / `POST` | `/sticker` | **表情包图库**：GET 返回分类、每张图的标签/大小/时间/停用状态与七档定义；POST 靠 `action` 做增删改 |
| `GET` | `/sticker/thumb` | 一张缩略图，查询参数 `c=分类key&n=文件名`。返回 data URL——面板在 iframe 里带不上鉴权头，图片不能走 `<img src>` |
| `POST` | `/tone` | 输出层预览：传一段文本，返回清理与拆条的结果，不写任何数据 |

`/manage` 支持的 `action`：

| 分类 | action |
|------|--------|
| 学习 | `learn` |
| 手动记忆 | `add_trait`、`add_traits_batch`、`update_trait`、`delete_trait` |
| 清空 | `clear_session`、`clear_history`、`clear_all`（`scope=learned\|manual\|history\|active\|all`） |
| 主动回复 | `set_active`（带 `enabled`）、`clear_active`（重置该群的计数与冷却） |
| 会话开关 | `set_session_override`、`clear_override` |
| 置顶 | `set_pin`（带 `session_id` 与 `pinned`），只影响面板显示顺序 |
| 人格档案 | `save_persona`（只写人工段）、`rebuild_persona`（重写自动段，不传 `session_id` 就全量） |
| 关系 | `set_intimacy`（带 `value`，-100~1000）、`set_nickname`（支持多个，逗号分隔）、`clear_nickname` |
| 事实 | 见上表 `POST /facts`，`/manage` 里也有同名动作 |
| 主动回复 | `apply_active_profile`（带 `id`：`quiet` / `balanced` / `lively` / `high` / `resident`） |
| 参数 | `set_setting`（带 `key` / `value`）、`reset_runtime` |
| 消耗 | `usage_detail`（带 `days`，返回近 N 天序列） |
| 花费上限 | `budget_release`（带 `on`：`true` 今天先放开，`false` 立刻收回） |
| 表情包 | 见下 |

涉及会话的 `action` 都要求 `session_id` 形如 `平台实例:GroupMessage:群号`，格式不对会直接拒绝——
这是防止写进一个永远不会命中的僵尸会话。`set_setting` / `reset_runtime` / `usage_detail` /
`budget_release` 不需要会话 ID。

`POST /sticker` 的 `action`：

| action | 参数 | 说明 |
|---|---|---|
| `add` | `label`、`filename`、`data`（base64 或 data URL）、`tags` | 上传一张图 |
| `auto_tag` | `label`、`name`、`apply` | 视觉模型打标；`apply=false` 只返回结果不落库，面板先填进输入框让用户改 |
| `untagged` | `limit` | 列出还没打标的图，给批量识别用 |
| `set_tags` / `set_enabled` | `label`、`name`、`tags` / `on` | 改标签、停用或启用单张图 |
| `move` / `remove` | `label`、`name`、`target` | 换分类、删图 |
| `add_category` / `update_category` / `remove_category` | `name`、`desc`、`keywords`、`key` | 分类的增改删。删分类前要求桶是空的 |

`POST /preview` 支持一个额外的 `active`（布尔）字段：传 `true` 时按**主动档位**的强度和字数上限
生成预览。插话用的强度是 60、被动是 100，只看被动会误判实际效果。

## 🔧 技术栈

- **无额外 pip 依赖**：只用 AstrBot SDK 内置模块和 AI 适配器本来就带的 `aiohttp`，不用 `pip install` 任何东西。
  菜单图用 Pillow 画，它是可选依赖——没装就把菜单退成纯文字，斗图和其余功能不受影响
- **纯本地存储**：全部数据都在 `data/plugin_data/<插件名>/` 内——16 个 JSON 文件（含关系、事实、画像、图库索引），
  外加 `stickers/` 图片本体、`token/` 按天账单与 `persona/` 人格档案，无数据库，也不往插件目录外写任何东西
- **存储隔离**：自动学习（`universal.json`）与手动记忆（`manual_traits.json`）物理分文件，
  学习流程不存在改动手动记忆的代码路径，不靠标记位或合并逻辑「尽量不覆盖」
- **注入方式**：`extra_user_content_parts` + `mark_as_temp()`，保护 LLM 前缀缓存
- **缓存护栏**：默认不改 system prompt；`style_override_deep` 是唯一会动它的开关，且默认关
- **容错设计**：LLM 输出 JSON 修复回退、embedding 超时降级、搜索异常降级成空结果、
  主动回复判定异常一律当「不插话」、tag 检索出错退回分类判定、打标失败不影响图库、统计写盘失败只记日志
- **代码分层**：入口 / 接口 / 钩子 / 工具 / 数据与算法，`TypedDict` 定义数据结构。
  三层「对人」各自独立成模块（`bond` / `facts` / `profile`），
  画像只单向依赖事实、事实只读关系档位，谁也不反向依赖谁

## 🙋 FAQ

**Q: 学习频率是怎么定的，会不会频繁烧钱？**
A: 不按时间、按消息量：某个群攒够 30 条新消息就学一次，且两次之间至少隔 30 分钟，
所以刷屏也不会连着烧。6 小时的 `analysis_interval_seconds` 只是兜底，防止长期没人聊的群
一直不更新。觉得太勤可以把 `learn_increment_messages` 调大；不想学的群在面板把该群的
学习开关关掉，连兜底也不会覆盖它。

**Q: 它到底会不会「越来越像我想要的群」？**
A: 会，但慢。一条风格要跨两轮被重复观察到才进注入，之后再按「跨天出现」加分，
所以临时冒出来的梗不会当天变成人格。想加速可以在学习库里手动批准，或者直接写进
「手动记忆」——那一份学习永远不碰。

**Q: 面板「累计成本」一直是 0？**
A: 因为还没跑过学习。启动后首轮检查需要等 300 秒，或先在群里发 `/学习风格` 手动触发一次。

**Q: 怎么导入自己的历史数据？**
A: 把 `universal.json` / `manual_traits.json` / `chat_history.json` 放进 `backup/<目录名>/`，
在面板点「导入备份」即可合并（同名特征保留更高熟练度，手动记忆按内容去重后追加）。
只有 `universal.json` 是必需的，另外两个缺了也能导。

**Q: 会保存聊天原文吗？**
A: 会，但只保存**尚未学习**的部分（默认每会话最多 200 条），学习完成后立即清空。已学到的只有提炼后的风格描述，不含原文。

**Q: 支持私聊吗？**
A: 支持，而且私聊是**单独一条学习库**（`learn_private_enabled`，默认关，主人私聊自动开）。
群聊学的是「这个群怎么说话」，私聊学不到群风格，但关系和事实在私聊里反而更有用——
「亲近」「老友」这两档只有私聊能到。

**Q: 关系和事实为什么默认关？**
A: 因为它们是「对人」的功能，涉及判断谁跟 bot 更亲、记住某个人身上发生过什么。
前者有人不想要（只是想让 bot 学学群里说话），后者涉及个人数据。默认关，想要的人自己开。

**Q: 开了关系，好感涨得特别慢，是不是没生效？**
A: 是设计。只认「bot 回过」的交互、15 分钟只判一次、群聊旁听一次 1.25、直接对话 3.1，
再叠一条越往后越难涨的曲线。按每天打满 96 次算：群里 3 天到「熟悉」，
之后**旁听不再涨**——想继续升温就在群里 @ 它、回复它，或者私聊，这三条路都还涨。
直接对话约 3 天熟悉、7 天亲近、12 天老友。
觉得慢先看 `daily_gain_cap`（默认 80，直接对话一天 26 次就撞到），把它调大是最快的办法；
其次是把 `growth_per_turn` 和 `group_passive_gain` 同比例调大，或把 `growth_curve_scale` 设 0 退回线性。

**Q: 记忆越攒越多，会不会越来越贵？**
A: 不会。**存储上限和注入配额是两件事**：存 300 条和存 20 条，每轮注入的都只是配额内那几条，
token 完全一样。会涨价的是「每轮注入多少字」，那由关系档位和画像上限控制，都有封顶。
所以「清理记忆」省的是文件体积和记忆质量，不是钱。

**Q: 事实记忆和人格画像有什么区别？**
A: 事实是**明细**（他下周三交论文、只喝冰美式），按话题挑，会遗忘；
画像是**概述**（他是谁、说话什么风格），每轮都在，忘得慢。
两层信息有重叠，所以画像已经概括过的事实会自动从事实段剔掉，不重复收费。

**Q: 换一个群，它还记不记得我？**
A: 记得。事实和画像都按 **QQ 号唯一**，换群照样生效；关系和好感也是全局累计。
按会话隔离的只有「群风格」——因为每个群的说话方式本来就不一样。

**Q: 为什么注入的内容里有「不要强行加 666」？**
A: 这是防「学步」约束。模型容易把学到的梗当成指令，每条回复都硬塞；加约束后只在语境合适时自然接梗。

**Q: 手动加的记忆会被下一轮学习覆盖吗？**
A: 不会。手动记忆在 `manual_traits.json`，学习只读写 `universal.json`，两边没有交叉路径。
就算学习恰好提炼出同样一条，也会因为重名被丢掉，以你写的为准。

**Q: 把熟练度改成 0 是不是就停用这条了？**
A: 不是。熟练度只影响排序和淘汰顺序，**只要条数没超过注入名额，熟练度 0 照样会被注入**。
真要停用只能删掉它。想压低优先级就调小，想彻底不用就删。

**Q: 手动改成高熟练度了，怎么注入里还是没有它？**
A: 看会话卡片头上的名额数，以及每条后面的「注入中 / 未入选」标记。常见原因是
手动记忆名额（`max_manual_inject`，默认 3）被其他手动条目占满了——名额是**手动记忆内部**
按熟练度排的，第 4 条再高也挤不进去。删掉几条或调大名额即可。

**Q: 新建会话记忆时「平台实例」该填什么？**
A: 从下拉里选，不要自己打字。它就是现有会话 ID 中冒号前面那段（例如 `bot1`），
不同部署可能不一样。填错会得到一个永远不生效的会话，而且不会报错——所以面板对
未知会话会二次确认。

**Q: 为什么手动记忆要单独存一个文件？**
A: 因为自动学习是「整表替换」语义。混在一张表里的话，下一轮提炼只要没复述到你那条，
它就被静默删了——而且你还不知道是学习删的。物理分开后，这种事在代码层面就不可能发生。

**Q: 设了 `reply_max_chars=80`，怎么还是回了 100 多字？**
A: 因为它只是一段「请控制在 80 字以内」的请求，不是硬限制。实测常见 90–120 字，模型对字数的
服从度就这样。真要硬切只能开 `reply_max_chars_hard`，代价是会切坏 markdown、链接和表情，
产出明显残句，比啰嗦更难看。

**Q: 强度 100 和强度 70 有什么区别？不都是满额注入吗？**
A: 名额上 70–99 是四分之三（5 条变 4 条），100 才是满额。让位是另一回事，看的是**阈值**：
默认阈值 100 等于不让位，所以默认配置下不管强度多少都听人设。把阈值调到 70，
强度 100 才变成每轮都按风格走，强度 85 是 85%。注意判定是「严格大于」——
强度 70 + 阈值 70 不让位。

**Q: 让位都命中了，模型还是按人设说话，是不是没生效？**
A: 这是「指令层优先级覆盖」，人格没被删掉，模型有一定概率仍然按人设走。所以是倾向不是保证。
想要更硬的效果开 `style_override_deep`，但那一轮 DeepSeek 的 system prompt 变了、
前缀缓存必然失效，输入按未命中价（30 倍）算。

**Q: 主动回复开了，群里一句话都没有，是不是坏了？**
A: 先按顺序排查：① 总开关和该群的会话开关；② 是不是在静默时段（默认 01:00–08:00）；
③ 最近 10 分钟是否少于 3 条消息（群太冷会直接跳过）；④ 今天是不是已经到日限 8 次；
⑤ 这个群的学习开关是不是关着——**主动回复的冷清判断读的是学习缓冲，关掉学习就没有主动回复**。
`/风格状态` 会显示「今日 N/8 · 下次评估 X 分钟后」，比猜快。

**Q: 开了主动回复之后出现两条回复？**
A: 大概率是 AstrBot 那边开了「群聊无需 @ 也回复」。插件命中插话时会 `should_call_llm(False)`
掐掉当前这条的原生回复，但 AstrBot 自己的策略仍可能再回一遍。把这个选项关掉。

**Q: 联网搜索配了 key 还是不会搜？**
A: 按这几条看：① `web_search_mode` 是不是 `plugin`（`inherit` 只是跟随 AstrBot、插件不管）；
② 搜出来的 key 是否真的取到了——`plugin` 模式下如果配不到 key，插件会把内置搜索工具
**一起摘掉**，表现就是完全不搜；③ 当天该群是不是已经用满 `web_search_daily_limit`（默认 20），
满额时工具根本不挂给模型；④ 这轮是不是主动插话——主动回复一律不搜索。

**Q: 斗图开了，群里一张表情包都没有？**
A: `/表情包` 能先看三项：总开关、图库张数、今天发了几次。都正常的话再查该群在不在
`session_blacklist` 里、对应分类是不是全停用了、同群是不是刚发过（有冷却）。
`keyword` 模式下只有命中词表才发，回复说得再热闹也不算。

**Q: 发了，但总挑不到对的那张？**
A: 多半是标签和群里的说法对不上。检索认的是「回复正文里出现了这张图的标签」，
标签写「美食展示」而群里说「放毒」就永远撞不上；改成群里的说法，或跑一次自动打标。
阈值调到 2.5 以上会变得很挑，1.0 容易一张「笑」把所有话都配了。

**Q: 自动打标要花钱吗，没配视觉模型怎么办？**
A: 一张约 ¥0.0007，只在手动点「识别」时才花。没有可用模型时回一句提示，标签保持原样，
图照常能发。默认用 AstrBot 全局的图片转述模型，也能单独指定——只是给图标词，不用强模型。

**Q: `/收表情` 说没拿到收藏表情？**
A: 它走协议端的 `fetch_custom_face`，LLBot / NapCat 一般支持，别的协议端可能没这个方法。
取不到不影响手动上传和 `/收图`，已经收进图库的也照常。

**Q: 预算到上限了，第二天怎么还锁着？**
A: 先看预算条是不是「今天已放开」——手动放开只管当天，过零点自动失效。
第二天仍然拦，多半是金额又花到线了，或者限额本来就调低了。

**Q: 消耗统计里的金额比我账单少？**
A: 对，它是**下限**。多轮工具调用中间那几次请求拿不到 usage，会漏计。插件自己发起的请求
（学习、判定、搜索次数）是精确的，每轮回复的 token 只能拿到最终响应那一份。

**Q: 想换 Tavily 划算吗？**
A: 先算额度：默认 20 次/群/天 × 10 群 × 30 天 = 6000 次/月，Tavily 免费额度是 1000 次/月。
要么把 `web_search_daily_limit` 压到 3 以下，要么继续用 DeepSeek（¥0.005/次，失败不计费）。
