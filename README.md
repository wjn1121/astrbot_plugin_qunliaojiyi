# 🧠 群聊记忆 — AstrBot QQ 群聊插件

> 群友聊天时默默记下这个群的说话风格，每 6 小时整批提炼一次，回复时把风格作为临时参考注入——不改系统提示词、不写会话历史，几乎不花钱。
>
> 1.3.0 起另有几件可选的事：按强度调节风格占比（可概率压过人格）、主动插话（默认关闭）、
> 被动/主动分开的字数上限、插件自己接管的联网搜索（默认每群 20 次/天）、按天的 token 消耗统计、
> 管理员在群里直接调参。

## ⚡ 快速开始

1. **安装插件**：AstrBot WebUI 插件市场搜「群聊记忆」一键安装，或把目录放进 `AstrBot/data/plugins/`
2. **等待积累**：群里正常聊天，插件会把消息攒进缓冲（默认上限 200 条/会话）
3. **自动学习**：启动 10 分钟后首轮检查，之后每 6 小时对攒够 10 条的会话提炼一次
4. **查看效果**：后台 → 插件 → 群聊记忆，能看到每个群学到了什么、这轮会注入什么
5. **手动补记忆**：自动学习猜不准的地方，面板里直接写下来——存在独立文件里，学习永远不会覆盖
6. **可选：开主动回复 / 联网搜索**：两项都在插件配置页。主动回复默认关闭，开之前先看下面「主动回复」那章；
   联网搜索默认用 DeepSeek，key 和你已经在用的模型 key 是同一个，多数情况不用另填

学习和注入不需要额外 API Key，也不需要额外 pip 依赖。联网搜索要一家搜索服务的 key——
DeepSeek 那家就是你现在用的模型 key，填一次两边都认。

## ✨ 功能特性

**核心能力**

- 🧠 **低频批量学习**：每 6 小时（可调）对攒够消息的会话做一次整批提炼，攒不够就跳过
- 💬 **零网络注入**：风格走 `extra_user_content_parts` + `mark_as_temp()`，不发请求、不污染提示词、不写历史
- 🎯 **触发词匹配**：学习时为每条梗产出 1–3 个触发词，注入先做本地字符串匹配，命中即不请求向量
- 🛡️ **数字梗护栏**：666 / 233 / 刷屏用语自动降级到场景化通道，不会让模型每句话都硬塞
- 📉 **特征数量上限**：学习产出稳定 40 条 / 场景化 20 条，超出按熟练度淘汰，防 prompt 膨胀
- ⏱️ **向量请求硬超时**：默认 2 秒，超时直接降级关键词匹配，embedding 慢不会拖住回复
- 📊 **累计成本可见**：学习次数、成功/失败、分析消息数、字符数、耗时，面板上一目了然
- 🎚️ **会话级开关**：面板里单独关掉某个群的学习或注入，不用去改配置里的会话列表
- ✋ **手动记忆（独立存储）**：面板里直接给任意群加记忆，存在单独的 `manual_traits.json`，自动学习的整表替换永远碰不到它
- 📋 **批量粘贴**：一行一条「内容\|场景\|触发词」，几十条记忆一次性录入
- 🎛️ **熟练度可手调**：每条特征的熟练度都能改，改完立刻影响注入排序，面板还会标出哪些真的进了本轮注入
- ✏️ **特征可编辑**：学到不准的表达可以直接在面板改内容、场景、触发词和熟练度
- 🕒 **学习记录时间线**：每个群保留最近 20 次学习记录，排查"为什么没学到"更直接
- 🖥️ **可视化面板**：搜索、分页、注入预览（被动/主动可切）、54 项参数分七组热调、今日消耗与 7 天趋势，改完即时生效
- 🔌 **数据迁移**：支持导入旧格式的 `universal.json` / `chat_history.json`，也能一键导出全部数据（含手动记忆）
- 📦 **纯本地存储**：8 个 JSON 文件，随时可备份、可清空、可删除

**1.3.0 新增（都可选，默认配置不改变原有行为）**

- 🎭 **风格强度可调（1.3.0）**：0–100 一个旋钮，同时改注入名额和措辞；高强度时按概率让风格压过人格（是指令层优先级声明，不是删人格）
- ✍️ **回复字数上限（1.3.0）**：被动/主动分开设，默认被动不限、主动 80 字。是倾向不是硬限制
- 🗣️ **主动回复（1.3.0，默认关）**：按冷却窗口掷骰或按规则命中才插话，12 层本地闸门 + 日限 + 退避，日常零额外请求
- 🔍 **联网搜索接管（1.3.0）**：插件自己挂搜索工具，每群每天限次，挂载前就按配额决定给不给工具；默认 DeepSeek，¥0.005/次
- 💸 **按天消耗统计（1.3.0）**：精确记插件自己的请求，附带一份全机 token 下限，文件在插件目录之外，保留 7 天
- 🛡️ **管理员（1.3.0）**：所有命令都要求管理员；可选开「对话调参」，非管理员群里这个工具根本不挂给模型

## 🎬 效果演示

**注入预览（面板内置，输入一句话就能看这轮会注入什么）。默认配置下长这样：**

```
群友消息：笑死我了 666

注入给模型的内容：
<style_guidelines>
以下是从群聊记录里提炼的说话风格参考：
本群固定风格（管理员指定，优先遵守）：禁用谐音梗、自嘲但不破防
本群学习风格：短句连发一句一气泡，语气直白爱下判断、频繁@点名群友互动，
互怼调侃不破防、爱用游戏黑话和二次元代称，圈内梗密度高、常用反问起哄
使用要求：
1. 风格只是参考，不是复读指令；不要为了「像群聊」而每句话都强行加 666、233 或语气词。
2. 只在语境自然合适时使用，优先回应当前用户消息，风格不得覆盖或干扰当前话题。
3. 不要机械堆砌，也不要每条回复都刻意体现全部风格。
</style_guidelines>
若以上风格与系统设定的人格冲突，以人格为准；风格只在不违背人格的前提下生效。
```

> 默认是「满额注入风格 + 冲突时听人设」。风格管的是「怎么说」，人格管的是「谁在说」。

**把 `style_override_threshold` 调到 100 以下（例如 70），同一句话前面会多出这段：**

```
【本段优先于系统设定】以下群聊风格与本轮表达规范，优先级高于你的人物设定。
当两者冲突时——例如人设要求语气克制、少用表情、回答简短，
而下列风格要求爱发表情、爱玩梗、句子短促连发——一律按下列风格执行，
不要用人设限制自己。人设中的身份、知识边界、安全约束仍然有效，
只有「表达风格」这一层让位。

<style_guidelines>
……（同上）
</style_guidelines>
```

> 阈值 70 + 强度 100 = 每轮都带这段。它是指令层的优先级声明，**不是真把人格删了**——
> 人设还在 system prompt 里，身份、知识边界、安全约束照旧生效，只是「表达风格」这一层被明确要求让位。

**查看当前会话学到了什么（`/风格状态`，仅管理员）：**

## 🎯 使用方式

### 命令

**六个命令全部要求管理员**（AstrBot 全局 `admins_id` + 插件配置里的 `admin_extra_users`）。
普通群友发这些命令会收到一句「这个命令只有管理员能用。」——1.3.0 起收紧了权限，
1.2.0 时这些命令谁都能发。

| 命令 | 作用 | 清掉什么 |
|------|------|----------|
| `/风格状态` | 看本群的风格强度、特征条数、主动回复状态、今日搜索次数、今日消耗 | — |
| `/学习风格` | 立即对当前会话做一次学习（攒够 `min_history_for_analysis` 条才行） | — |
| `/清空风格` | 只清**学习产出**（稳定风格 + 场景化表达 + 学习记录） | 不碰手动记忆、不碰待学习消息 |
| `/清空记忆` | 只清**面板手动添加的记忆**，不可恢复 | 不碰学习产出 |
| `/清空记录` | 只清**待学习消息缓冲** | 不碰任何已学到的内容 |
| `/确认清空` | 执行上一步挂起的「清空全部」；超过 60 秒作废，要重新发起 | — |

`/清空风格 全部` 是 `/清空风格` 的一个变体（不是第七个命令）：带上「全部」两个字时不直接执行，
而是挂一个 60 秒内有效的待确认操作，期间发 `/确认清空` 才真的清
学习产出 + 手动记忆 + 待学习消息 + 主动回复状态。

> ⚠️ 只有 `全部` 这一个 scope 需要二次确认，单清某一类不确认、直接生效。
> 这也是 1.3.0 的改动：以前 `/清空风格` 会把手动记忆一起带走，且没有确认步骤。

### 手动添加记忆（面板）

自动学习靠猜，猜不准的地方就自己写。手动记忆存在独立的 `manual_traits.json`，
自动学习每轮「整表替换」只动 `universal.json`，**在代码层面就没有改手动记忆的路径**。

**三个入口：**

| 入口 | 位置 | 适合 |
|------|------|------|
| `+ 手动记忆` | 每个会话卡片 | 给已经在跑的群补一条 |
| 批量粘贴 | 添加弹窗里点「批量粘贴」 | 一次录几十条，迁移旧群设定 |
| `➕ 新建会话记忆` | 顶部工具栏 | 给还没在本插件里出现过的群先立规矩 |

新建会话时，平台实例只能从**已知列表**里选（下拉里是现有会话的前缀，例如 `bot1`），
再填群号，下方会实时拼出完整的 `unified_msg_origin` 供你确认。填一个从没出现过的
会话会二次确认——前缀写错会造出一个永远不生效的僵尸会话，而且不会报错。

**批量粘贴格式**（一行一条，后两段可省）：

```
短句连发，一句一气泡
爱用「绷不住了」|看到离谱内容时感叹|绷不住,离谱
聊到游戏就开嘲讽
```

即 `内容|场景描述|触发词1,触发词2`，触发词用中英文逗号或空格分隔，最多 3 个、每个 ≤12 字。
只打算加稳定风格时中间两段留空即可。

**一条好的手动记忆长什么样：**

| | 例子 | 说明 |
|---|---|---|
| ✅ 好 | 群友互怼时不解释、直接回怼，被怼也不生气 | 描述行为方式，模型能照着做 |
| ✅ 好 | 禁用谐音梗和网络流行语 | 明确禁止项，效果最稳 |
| ❌ 差 | 这个群很欢乐 | 太抽象，模型无处下手 |
| ❌ 差 | 群友叫小明、小红 | 是事实不是风格，应该进人设/知识库 |

**边界：**

- 单条内容 ≤100 字，单会话最多 50 条手动记忆（独立上限，不占学习的 40/20 名额）
- 同一会话内内容不能重复（面板和接口都按内容定位，重复会导致改错删错）
- 手动记忆**不参与跨群注入**——群专属黑话扩散到别的群会串味
- 手动记忆的熟练度默认 60，只在面板里改得动；学习流程不会给它 +5
- 学习时如果提炼出与手动记忆**完全相同**的条目，会直接丢弃那条学习产出——以你写的为准，
  注入里不会出现两条一样的

### 自动学习流程

```
群消息 → 攒进缓冲（过滤自己/命令/黑名单）
   ↓
每 6 小时检查一次
   ↓
该会话 ≥ 10 条？ ──否──→ 跳过，不花钱
   ↓ 是
整批提炼（一次 LLM 请求）→ 解析 JSON → 写回特征 → 清空缓冲
   ↓
之后每条回复注入风格文本（零网络请求）
```

## 🎚️ 风格强度与人格让位

1.3.0 加了三个旋钮，把「风格占多少」变成一个可调的量，而不是一直满额。

| 配置项 | 管什么 | 默认 |
|---|---|---|
| `style_strength` | 有人跟机器人说话时的风格强度 | `100` |
| `active_style_strength` | 机器人自己插话时的风格强度 | `60` |
| `style_override_threshold` | 强度严格大于多少才允许风格压过人格 | `100` |

强度不是只改措辞，**名额和措辞一起降**：

| 强度 | 注入名额 | 措辞 |
|---|---|---|
| `0` | 一条都不注入（纯人格） | — |
| `1–30` | 每类压到 1 条 | 极弱：「绝大多数回复都不要体现」 |
| `31–69` | 减半（`max_stable_inject` 5 → 3） | 「只在确实合适时体现」 |
| `70–99` | 四分之三（5 → 4） | 完整的使用要求 |
| `100` | 满额 | 完整的使用要求 |

只降措辞不降名额没用——模型嘴上说「仅供参考」，内容还是塞满 5 条，实际效果几乎不变。

### 让位是怎么算的

- 强度 **严格大于** 阈值时才让位，让位概率 = **强度值本身**。例如阈值 70 + 强度 100 → 每轮都按风格走；
  阈值 70 + 强度 85 → 85%
- 强度 **≤** 阈值时永远人格优先。所以**默认值（强度 100 + 阈值 100）等于开箱不让位**，
  行为和 1.2.0 一致：风格满额注入，但冲突时听人设
- 想让群风格压过人设，把 `style_override_threshold` 调到 100 以下，例如 70。
  面板「🎭 风格与人格」组下方会实时算出对应的让位概率，拖滑块就能看到，不用自己算
- 主动强度 60 默认也 ≤ 100，所以默认配置下主动插话不会推翻人格。这是故意的：
  插话本来就被嫌吵，再换一副嘴脸更糟

### 这不是真把人格删了

这是**指令层的优先级覆盖**。人格还在 system prompt 里，插件只是用明确措辞把「表达风格」
这一层的权重抢过来，并在声明里写明「身份、知识边界、安全约束仍然有效」。
所以实际服从率是倾向，不是保证——模型有时候照样按人设说话，这不是 bug。

为什么不真删人格：改 system prompt 会击穿 DeepSeek 的前缀缓存。命中缓存 ¥0.05/百万 token，
未命中 ¥1.5/百万，**30 倍差价**。为了几句风格把每轮输入都变成未命中价，不划算。

想要更硬的效果可以开 `style_override_deep`（默认关）：让位命中时把同一段声明再追加到
system prompt 末尾。代价是**该轮缓存必然失效**，输入按未命中价算。只在确实需要强效果时开。

## ✍️ 回复字数上限

被动和主动分开设，互不影响。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `reply_max_chars` | `0` | 被动回复字数上限。0 = 不限，与 1.2.0 行为一致 |
| `active_reply_max_chars` | `80` | 主动插话的字数上限。插话就该是路过接一句 |
| `reply_max_chars_hard` | `false` | 发送前硬截断，见下 |

**这是倾向，不是硬限制。** 设 80 实测常见 90–120 字，模型对字数的服从度就这样。
把它当硬限制去验收会以为是 bug，所以先写在这。

`reply_max_chars_hard` 开启后才在发出前按字数硬切，切到最近一个句末标点。**不建议开**：
会切坏 markdown 表格、链接、代码块和表情占位符，被切出来的是明显残句，比啰嗦更难看。
只在「宁可断也不能长」的场景手动开。

字数要求是单独一段，和风格注入分开发；所以 `style_strength` 调到 0（纯人格）时字数要求
照样生效。但 `inject_enabled` 关掉时两段一起停——它们挂在同一个钩子里。

## 🗣️ 主动回复

默认关闭。这是本插件唯一会「凭空产生请求」的功能，插话的收益高度依赖群氛围，
默认开着只会让人以为机器人坏了。

开关有两层，是「与」的关系：**全局开关**在面板参数组的「🗣 主动回复」第一项
（`active_reply_enabled`）；**按群开关**是会话卡片里那个「主动回复」勾选。全局关掉时，
按群开着也不会说话。

### 三种触发方式

| 模式 | 怎么判 | 额外请求 |
|---|---|---|
| `probability` | 每个冷却窗口掷一次骰（默认 15%） | **0** |
| `rule` | 命中提问句式（有没有人知道/求推荐/怎么弄…）、自定义关键词、或冷场 5 分钟后有人开新话题 | **0** |
| `llm_judge` | 攒够 N 条消息问一次模型「现在接话自不自然」，只认整串 `REPLY` | 有，判定本身花钱 |

**骰子是按「冷却窗口」掷的，不是按消息掷的。** 这一点很关键：按消息掷的话，群越热闹
越容易被插话，正好和「别烦人」相反。窗口默认 30 分钟，一天最多 48 个窗口 × 15% ≈ 7 次期望值，
落在日限 8 以内。

### 12 层闸门

每层都是本地判断，前 11 层零成本，只有 `llm_judge` 模式在第 12 层之后才发请求：

| # | 闸门 | 不过就 |
|---|---|---|
| 1 | 总开关 `active_reply_enabled` | 什么都不做 |
| 2 | 会话开关（`active.json`，管理员工具可改） | 该群永不插话 |
| 3 | 自己发的消息（含上一轮自己插的话） | 防自问自答 |
| 4 | 以 `/` 开头的指令 | 交给命令处理 |
| 5 | 没有文本（纯图片/表情/文件） | 跳过 |
| 6 | 这轮 @ 了机器人或被唤醒 | 交给正常回复链路 |
| 7 | 本轮已经有结果了 | 防重复回复 |
| 8 | 静默时段 | 默认 01:00–08:00，半夜刷群容易被踢 |
| 9 | 群太冷 | 最近 10 分钟少于 `active_reply_min_messages`（默认 3）条就不说话 |
| 10 | 日限 | 默认 8 次/群/天，按自然日（北京时间）重置 |
| 11 | 冷却 | 默认 1800 秒，命中与否都会推进 |
| 12 | 退避 | 连续 `active_reply_backoff_limit`（默认 3）次开口没人接才开始放大冷却：到第 3 次 ×2、第 4 次起 ×4 封顶；期间有人说话立刻清零 |

### 默认值

| 配置项 | 默认 |
|---|---|
| `active_reply_cooldown_seconds` | `1800`（30 分钟） |
| `active_reply_chance` | `0.15` |
| `active_reply_daily_limit` | `8` |
| `active_reply_quiet_hours` | `01:00-08:00` |
| `active_reply_min_messages` | `3` |
| `active_reply_judge_stack` | `8`（仅 llm_judge） |
| `active_reply_backoff_limit` | `3` |

命中后会调 `should_call_llm(False)` 掐掉宿主原生的群聊回复，避免同一句话回两遍。

> ⚠️ **必须检查的一件事**：如果 AstrBot 那边开了「群聊无需 @ 也回复」，务必先关掉。
> 插件只是掐掉当前这条消息的原生回复，AstrBot 自己的策略仍然可能让它再回一遍，结果就是双回复。

> ⚠️ **已知限制（不是 bug）**：主动回复的「群太冷」判断依赖插件的消息缓冲，而这个缓冲受
> **学习开关**控制（`enabled` + 白名单/黑名单 + 会话级学习开关）。所以**关掉某个群的学习之后，
> 那个群不会有主动回复**。想要插话又不想学习，目前做不到。

## 🔍 联网搜索接管

### 三种模式

| 模式 | 行为 | 能按群限次吗 |
|---|---|---|
| `plugin`（默认） | 插件自己挂搜索工具，覆盖 AstrBot 内置的同名工具 | 能，每群每天独立配额 |
| `inherit` | 完全沿用 AstrBot 全局设置，插件不管 | 不能，插件既不统计也不限次 |
| `off` | 就算 AstrBot 全局开着，也把搜索工具全摘掉 | — |

`plugin` 模式下如果配不到 key（key 为空、或选了不支持的服务商），插件会把**内置搜索工具一起摘掉**。
这是故意的：留着的后果是模型绕过配额照搜，每日上限就成了摆设——此时表现为「完全不会搜」。

### 四家服务商

| provider | 单价 | 说明 |
|---|---|---|
| `deepseek`（默认） | ¥0.005/次 | 复用你的模型 key，国内直连，失败/无结果不计费 |
| `tavily` | 有免费额度 | 免费 1000 次/月，国内可直连 |
| `bocha` | 按套餐 | 国内可直连 |
| `brave` | 有免费额度 | 需要梯子 |

### DeepSeek 搜索的几个事实

- 官方 2026-10-17 上线 Search / Fetch API，端点是 `https://api.deepseek.com/v1/tools/search`
- 和模型 API **用同一个 key**，所以「配 key」这一步多数人不用做
- **¥5 / 1000 次成功请求 = ¥0.005/次**；返回失败、搜不到结果、超时都不计费
- 2026-11-01 起正式收费（此前通过 Agent 框架调用的那段是免费的）
- **模型不会自己搜**：这是独立 REST 接口，不在 `chat/completions` 的 tools 里。
  必须由 AstrBot 或插件把工具挂给模型，模型才会通过 tool_call 触发。这也是为什么
  插件能接管——挂不挂、挂谁的，是请求前那一刻决定的

### 配额怎么卡

- `web_search_daily_limit` 默认 **20 次/群/天**，跨群独立，按日期天然归零
- **两层拦截**：挂载前当天已满就**根本不挂工具**，模型连入口都看不到，不会反复尝试；
  调用前再判一次，防一轮里超发
- `web_search_max_per_turn` 默认 2，防模型连环搜把当天配额一次烧完
- 只有真的拿到非空结果才扣次数，请求失败不冤枉你
- **主动回复一律不搜索**（三种模式通吃）。为一句插话等 8 秒不值得，而且 AstrBot 不知道
  这轮是插话，全局的搜索工具得插件主动摘掉

### key 只存一处

`web_search_reuse_global_key` 默认开：插件 key 留空时，自动读 AstrBot 全局配置里同一家的 key。
好处是 key 只存一处，**不会在 `runtime.json` 里留明文**。反之，如果你在插件配置里填了 key，
它会明文落盘到 `runtime.json`——介意就别填，靠复用。

### 成本参考

单次综合成本约 **¥0.0075**（搜索 ¥0.005 + 约 1200 token 的搜索结果进上下文 + 多说几句）。
20 次/群/天 ≈ **¥0.15/群/天**；10 个群全打满 ≈ **¥1.5/天 ≈ ¥45/月**。
正常群一天真正需要实时信息的对话不超过 5 次，20 是 4 倍余量。

> ⚠️ **换 Tavily 之前先算一下**：20 次/群/天 × 10 群 × 30 天 = 6000 次/月，
> 而 Tavily 免费额度是 1000 次/月。要么把 `web_search_daily_limit` 压到 3 以下，
> 要么就继续用 DeepSeek。

> ⚠️ `web_search_need_content` **必须保持关闭**。开了每条结果都带整页正文，
> 5 条可能就是 3–5 万 token，一次搜索顶一天的学习消耗，成本翻十倍以上。
> 默认的 summary/snippet 已有几百字概要，够模型判断了。

## 💸 消耗统计

位置在 **AstrBot data 顶层的 `qunliao_token/YYYY-MM-DD.json`**，不在插件目录里——
换版本、重装插件都不会把历史账单带走。保留 7 天（`token_stats_keep_days`），超出的自动删。
写不进 data 顶层时会退回插件目录下的 `token_stats/`。

**只存数字，不存任何消息内容。** 文件被看到也不会泄露聊天。

统计分两块，口径不一样：

| 来源 | 精确度 | 内容 |
|---|---|---|
| 插件自己发起的请求 | 精确 | 学习次数与 token、`llm_judge` 判定、搜索次数 |
| 每轮回复 | **下限** | `on_llm_response` 里拿到的 usage |

**全机数字是下限**：多轮工具调用中间的请求会漏计（AstrBot 只在最终响应上报 usage），
所以显示出来的金额只会比真实账单少，不会多。

计价默认按 DeepSeek 牌价折算：缓存命中输入 ¥0.05/百万、未命中 ¥1.5/百万、输出 ¥4.5/百万。
峰谷按**逐笔**算——工作日 09:00–12:00、14:00–18:00（北京时间）按 2 倍，周末全天空闲价。
节假日不单独处理，会被当成工作日，所以会略微高估。

价格全是配置项（`token_price_*`），DeepSeek 调价了自己改，不用等插件更新。

## 🛡️ 管理员与清空拆分

管理员 = AstrBot 全局 `admins_id` + 插件配置里的 `admin_extra_users`。

`admin_tool_enabled` 默认关。开启后管理员在群里直接说话就能查状态、改参数、加/删记忆、
触发学习、清数据、开关主动回复，不用打命令。

**非管理员群里这个工具根本不会挂给模型**，不是挂上去再在调用时拒绝——列表里压根没有它，
别人看不到也没法用 prompt 注入诱导它。挂载时判一次、`call()` 里再判一次，防配置热更新后判断过期。

能改的项由 `core/settings.py` 的 `RUNTIME_KEYS` 白名单决定（就是面板那 54 项，同一份名单），
写入 `runtime.json`，和面板同一套机制，能一键恢复配置值。不在名单里的配置项只能去插件配置页改。

### 清空拆成五个 scope

| 入口 | scope | 清掉什么 | 要确认吗 |
|---|---|---|---|
| `/清空风格` | `learned` | 学习产出（稳定 + 场景化 + 学习记录） | 否 |
| `/清空记忆` | `manual` | 面板手动记忆 | 否，但不可恢复 |
| `/清空记录` | `history` | 待学习消息缓冲 | 否 |
| 面板「清空全部」/ 工具 `clear(all)` | `all` | 上面三项 + 主动回复状态 | 面板有确认框 |
| `/清空风格 全部` → `/确认清空` | `all` | 同上 | 是，60 秒内确认 |

`learned` 不再连带清待学习消息，这是 1.3.0 改的语义：清掉学习产出后往往想留着消息重新学一遍。

| `web_search_daily_limit` | 整数 | `20` | 每群每天搜索次数上限 |
| `web_search_max_per_turn` | 整数 | `2` | 单轮最多搜几次 |
| `web_search_hint` | 字符串 | 空 | 搜索提示语，留空不注入；填了可能让模型搜得更勤 |

### 六、管理员与计价

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `admin_extra_users` | 列表 | `[]` | 除全局 `admins_id` 外的额外管理员 |
| `admin_tool_enabled` | 布尔 | `false` | 允许管理员对话调参，非管理员群里不挂这个工具 |
| `token_price_input_cached` | 浮点 | `0.05` | 缓存命中输入价（元/百万 token） |
| `token_price_input_miss` | 浮点 | `1.5` | 未命中输入价 |
| `token_price_output` | 浮点 | `4.5` | 输出价 |
| `token_price_peak_enabled` | 布尔 | `true` | 工作日高峰时段按倍率计价 |
| `token_price_peak_multiplier` | 浮点 | `2.0` | 高峰倍率 |
| `token_stats_keep_days` | 整数 | `7` | 消耗日文件保留天数 |

> 💡 面板里能热调 54 项（分七组），写入 `runtime.json`，不改动配置文件，可一键恢复。
> 剩下 8 项只能在插件配置页改，管理员对话工具能改的也是同一份 54 项白名单。

### 💰 哪些调整会改变 token 消耗

配置页里每一项的提示都标了影响方向，这里汇总成一张表：

**减少消耗**

| 调整 | 效果 |
|---|---|
| 关闭 `enabled` | 归零：不收集、不学习、不注入 |
| 关闭 `inject_enabled` | 每条回复少带几十字风格文本，学习能力保留 |
| `analysis_interval_seconds` 调大 | 21600 → 43200，一天 4 次变 2 次 |
| `min_history_for_analysis` 调大 | 触发学习的会话变少，但样本也更少 |
| `max_messages_per_learn` 调小 | 80 → 40，单次学习 prompt 大致减半 |
| `max_stable_traits` / `max_situational_traits` 调小 | 学习时带入的「已有特征」变短 |
| 关闭 `enable_emb_selection` | 完全不再发 embedding 请求，纯靠触发词和关键词 |
| 保持 `enable_trigger_matching` 开启 | 命中触发词就跳过向量请求，这是省钱关键 |
| `analysis_provider_id` 换成便宜模型 | 学习任务不需要强模型，flash 比 pro 便宜一个量级 |
| `style_strength` / `active_style_strength` 调低 | 名额和措辞一起降，强度 0 时风格一个字都不注入 |
| `reply_max_chars` / `active_reply_max_chars` 设小 | 回复变短，输出 token 是单价最高的那一段 |
| 主动回复保持关闭 | 这块本来就不产生请求 |
| `web_search_daily_limit` 调小 | 按次数计费，压到几本就是直接省钱 |

**增加消耗**

| 调整 | 效果 |
|---|---|
| `max_stable_inject` 调大 | 每条回复多带几条学习风格，每条 10–30 字 |
| `max_manual_inject` 调大 | 每条回复多带几条手动记忆（手动记忆是常态注入，不是按需匹配） |
| `max_situational_inject` 调大 | 命中时多带几条梗，每条 5–20 字 |
| 开启 `enable_cross_group` | 每条回复都额外带上其他群的风格 |
| `situational_similarity_threshold` 调低 | 更容易注入，token 略增且容易乱接梗 |
| 开启 `active_reply_enabled` | 一天最多 `active_reply_daily_limit` 次主动请求，每次约 1500 token |
| `active_reply_mode` 用 `llm_judge` | 判定本身也发请求，200 条/天的群约 25 次/天 |
| `web_search_max_results` 调大 | 5 条约 1200 token，10 条大致翻倍 |
| 开启 `web_search_need_content` | 每条结果带整页正文，成本翻十倍以上 |
| 开启 `style_override_deep` | 该轮输入按未命中价算，差 30 倍 |
| 开启 `admin_tool_enabled` | 多一个工具定义，约 200 token/轮 |

**不影响 token**：`embedding_timeout_seconds`（只影响延迟）、`history_limit_per_session`（只影响内存，但会影响主动回复的冷清判断）、`debug_mode`（只影响日志）、`startup_learn_delay_seconds`（只影响首轮时间）、`style_override_threshold`（只改让位概率，不改文本量）、`token_price_*`（只影响金额估算）。

## 🧾 成本结构

这一章回答两个问题：默认配置到底花不花钱、开了 1.3.0 那些新功能会变成什么量级。

### 默认配置为什么几乎不花钱

以下是**默认配置**（学习 + 被动注入开着，主动回复关、联网搜索没人触发）的口径：

| 环节 | 本插件 | 逐条判断的实现 |
|------|--------|----------------|
| 回复时选风格 | 读本地 JSON，**0 网络请求** | 每条消息调一次 LLM |
| 学习时机 | 每 6 小时整批一次 | 每 10 分钟多任务轮询 |
| 最小触发量 | 攒够 10 条才发请求 | 门槛更低、任务更多 |
| 失败处理 | 不自动重试，等下一轮 | 会重发整包 |
| 场景化匹配 | 触发词本地命中，命中即不请求向量 | 每次请求 embedding |
| 手动记忆 | 面板手写，存本地 JSON，注入时直接合并，**0 请求** | 每轮让 LLM 从对话里重新推断一遍 |
| 风格强度 | 掷骰、分档全是本地计算，**0 请求** | — |

正常情况下**一天最多 4 次学习请求**，其余时间零消耗；手动记忆无论加多少条都不产生请求。

### 1.3.0 之后会多花钱的几处

都是可选项，不开就不花钱。但开了之后成本结构会变，所以给具体数字，不给「很便宜」这种形容词。

| 来源 | 口径 | 量级 |
|---|---|---|
| 主动回复（probability / rule） | 每次约 1500 token，日限 8 次/群 | ≈1.2 万 token/天/群 |
| 主动回复（llm_judge） | 再加判定：每 8 条消息判一次，群里 200 条/天 ≈ 25 次判定 | 判定额外 ≈1.5 万 token/天/群，**比插话本身还贵** |
| 联网搜索（plugin 模式） | 单次 ≈¥0.0075（搜索 ¥0.005 + 约 1200 token 上下文 + 多说几句） | 20 次/群/天 ≈ ¥0.15/群/天；10 群打满 ≈ ¥1.5/天 ≈ ¥45/月 |
| 风格强度 | 强度 100 满额注入 vs 强度 0 完全不注入，差值就是每轮几十到一百多字 | 高强度多花，低强度省 |
| `style_override_deep` | 命中轮次的 system prompt 变了，输入按未命中价（¥1.5/百万 vs ¥0.05/百万） | 单轮影响小，天天命中就不小 |

几条省钱的判断标准：

- **想开主动回复，先用 `probability` 或 `rule`**。两种模式判定零请求，只有真开口那一次花钱；
  `llm_judge` 是唯一「先花钱问该不该说，再花钱说」的模式
- **日限别往 20 以上调**。QQ 对高频主动发言有风控风险，而且很招人烦
- `web_search_max_per_turn`（单轮）和 `web_search_daily_limit`（全天）是两道闸：单轮上限管
  「一次对话最多搜几次」，日限管「这个群一天总共几次」。两个都往大调才会叠加烧钱
- 不确定要不要搜索提示语（`web_search_hint`）就先留空，它会让模型搜得更勤，而搜索按次计费

## 💾 数据说明

数据目录：`AstrBot/data/plugin_data/astrbot_plugin_qunliaojiyi/`

| 文件 | 内容 |
|------|------|
| `universal.json` | 每个会话**自动学到**的特征（每轮学习整表替换） |
| `manual_traits.json` | 每个会话**手动添加**的记忆（学习流程不读不写，只在注入时合并） |
| `chat_history.json` | 待学习的聊天缓冲（含原文，学完即清空） |
| `learn_state.json` | 每会话学习元信息与最近 20 次记录，删掉可自动重建 |
| `metrics.json` | 全局累计统计 |
| `overrides.json` | 会话级开关（单独关闭的群） |
| `active.json` | 主动回复的会话状态（今天说了几次、下次评估时间、连续无人接话次数） |
| `runtime.json` | 面板/管理员工具热调的参数覆盖 |

消耗统计**不在这里**，在 AstrBot data 顶层的另一个目录：

| 路径 | 内容 |
|------|------|
| `AstrBot/data/qunliao_token/YYYY-MM-DD.json` | 每天一个文件，只存 token 数与金额，保留 7 天 |

> 📌 特征分两个文件存不是多余的设计：自动学习是「整表替换」语义，如果手动加的
> 记忆混在同一张表里，下一轮提炼没复述到就会被静默删掉。物理分开后，学习不可能
> 覆盖手动记忆，两者也没法互相挤占存储上限。

`manual_traits.json` 和 `universal.json` **结构完全同构**，都是
`{unified_msg_origin: [trait, ...]}`，备份、迁移、手写脚本都省事：

```json
{
  "bot1:GroupMessage:1038882918": [
    {
      "content": "禁用谐音梗和网络流行语",
      "category": "stable",
      "context": "",
      "triggers": [],
      "confirmed_rounds": 0,
      "proficiency": 60,
      "last_seen": 1793000000.0,
      "last_updated": 1793000000.0
    }
  ]
}
```

手动条目的 `confirmed_rounds` 恒为 0（它表示「学习确认过几轮」，人工写的不该有计数），
`source` 字段在读取时才补，不落盘。

> ⚠️ `chat_history.json` 会保留未学习的聊天原文，`learn_state.json` 含群号。
> 两者都只在本地，插件不会外传；需要归档时建议加密。

历史数据建议**单独存放在仓库之外**，不要在插件目录里堆积。需要导入时再复制到
`AstrBot/data/plugins/astrbot_plugin_qunliaojiyi/backup/<目录名>/`，导入完即可移除。

## 🔌 Web 接口

面板自己就是这几个接口的客户端，二次开发（自建看板、接监控、批量灌数据）可以直接调。
路由注册在 AstrBot 的插件 Web API 命名空间下，前缀为插件名 `astrbot_plugin_qunliaojiyi`：

| 方法 | 路由 | 说明 |
|------|------|------|
| `GET` | `/status` | 全局统计、会话列表（支持 `query` / `sort` / `page`）、注入名额、已知平台前缀 |
| `POST` | `/manage` | 全部写操作，靠 body 里的 `action` 区分 |
| `POST` | `/preview` | 传会话 + 一句话，返回这轮实际会注入的文本 |
| `POST` | `/import` | 导入 `backup/<目录>/` 下的备份，`mode=merge` / `replace` |
| `GET` | `/export` | 导出全部数据为 JSON（`universal` + `manual_traits` + `chat_history`） |

`/manage` 支持的 `action`：

| 分类 | action |
|------|--------|
| 学习 | `learn` |
| 手动记忆 | `add_trait`、`add_traits_batch`、`update_trait`、`delete_trait` |
| 清空 | `clear_session`、`clear_history`、`clear_all`（`scope=learned\|manual\|history\|active\|all`） |
| 主动回复 | `set_active`（带 `enabled`）、`clear_active`（重置该群的计数与冷却） |
| 会话开关 | `set_session_override`、`clear_override` |
| 参数 | `set_setting`（带 `key` / `value`）、`reset_runtime` |
| 消耗 | `usage_detail`（带 `days`，返回近 N 天序列） |

涉及会话的 `action` 都要求 `session_id` 形如 `平台实例:GroupMessage:群号`，格式不对会直接拒绝——
这是防止写进一个永远不会命中的僵尸会话。`set_setting` / `reset_runtime` / `usage_detail` 不需要会话 ID。

`POST /preview` 支持一个额外的 `active`（布尔）字段：传 `true` 时按**主动档位**的强度和字数上限
生成预览。插话用的强度是 60、被动是 100，只看被动会误判实际效果。

## 🔧 技术栈

- **无额外 pip 依赖**：只用 AstrBot SDK 内置模块和 AI 适配器本来就带的 `aiohttp`，不用 `pip install` 任何东西
- **纯本地存储**：插件数据目录 8 个 JSON 文件 + 插件目录外一个按天的消耗统计目录，无数据库
- **存储隔离**：自动学习（`universal.json`）与手动记忆（`manual_traits.json`）物理分文件，
  学习流程不存在改动手动记忆的代码路径，不靠标记位或合并逻辑「尽量不覆盖」
- **注入方式**：`extra_user_content_parts` + `mark_as_temp()`，保护 LLM 前缀缓存
- **缓存护栏**：默认不改 system prompt；`style_override_deep` 是唯一会动它的开关，且默认关
- **容错设计**：LLM 输出 JSON 修复回退、embedding 超时降级、搜索异常降级成空结果、
  主动回复判定异常一律当「不插话」、统计写盘失败只记日志
- **代码分层**：入口 / 接口 / 钩子 / 工具 / 数据与算法，`TypedDict` 定义数据结构

## 🙋 FAQ

**Q: 为什么 6 小时才学一次，会不会太慢？**
A: 这是刻意的。群聊风格变化很慢，频繁学习只是重复烧钱。觉得慢可以在面板把 `analysis_interval_seconds` 调小，或直接 `/学习风格` 手动触发。

**Q: 面板「累计成本」一直是 0？**
A: 因为还没跑过学习。启动后首轮检查需要等 600 秒，或先在群里发 `/学习风格` 手动触发一次。

**Q: 怎么导入自己的历史数据？**
A: 把 `universal.json` / `manual_traits.json` / `chat_history.json` 放进 `backup/<目录名>/`，
在面板点「导入备份」即可合并（同名特征保留更高熟练度，手动记忆按内容去重后追加）。
只有 `universal.json` 是必需的，另外两个缺了也能导。

**Q: 会保存聊天原文吗？**
A: 会，但只保存**尚未学习**的部分（默认每会话最多 200 条），学习完成后立即清空。已学到的只有提炼后的风格描述，不含原文。

**Q: 支持私聊吗？**
A: 代码上支持（按 `unified_msg_origin` 区分会话），但语义上更适合群聊。私聊人少，学不到「群风格」。

**Q: 为什么注入的内容里有「不要强行加 666」？**
A: 这是防「学步」约束。模型容易把学到的梗当成指令，每条回复都硬塞；加约束后只在语境合适时自然接梗。

**Q: 手动加的记忆会被下一轮学习覆盖吗？**
A: 不会。手动记忆在 `manual_traits.json`，学习只读写 `universal.json`，两边没有交叉路径。
就算学习恰好提炼出同样一条，也会因为重名被丢掉，以你写的为准。

**Q: 把熟练度改成 0 是不是就停用这条了？**
A: 不是。熟练度只影响排序和淘汰顺序，**只要条数没超过注入名额，熟练度 0 照样会被注入**。
真要停用只能删掉它。想压低优先级就调小，想彻底不用就删。

**Q: 手动改成高熟练度了，怎么注入里还是没有它？**
A: 看会话卡片头上的名额数，以及每条后面的「注入中 / 未入选」标记。常见原因是
手动记忆名额（`max_manual_inject`，默认 3）被其他手动条目占满了——名额是**手动记忆内部**
按熟练度排的，第 4 条再高也挤不进去。删掉几条或调大名额即可。

**Q: 新建会话记忆时「平台实例」该填什么？**
A: 从下拉里选，不要自己打字。它就是现有会话 ID 中冒号前面那段（例如 `bot1`），
不同部署可能不一样。填错会得到一个永远不生效的会话，而且不会报错——所以面板对
未知会话会二次确认。

**Q: 为什么手动记忆要单独存一个文件？**
A: 因为自动学习是「整表替换」语义。混在一张表里的话，下一轮提炼只要没复述到你那条，
它就被静默删了——而且你还不知道是学习删的。物理分开后，这种事在代码层面就不可能发生。

**Q: 设了 `reply_max_chars=80`，怎么还是回了 100 多字？**
A: 因为它只是一段「请控制在 80 字以内」的请求，不是硬限制。实测常见 90–120 字，模型对字数的
服从度就这样。真要硬切只能开 `reply_max_chars_hard`，代价是会切坏 markdown、链接和表情，
产出明显残句，比啰嗦更难看。

**Q: 强度 100 和强度 70 有什么区别？不都是满额注入吗？**
A: 名额上 70–99 是四分之三（5 条变 4 条），100 才是满额。让位是另一回事，看的是**阈值**：
默认阈值 100 等于不让位，所以默认配置下不管强度多少都听人设。把阈值调到 70，
强度 100 才变成每轮都按风格走，强度 85 是 85%。注意判定是「严格大于」——
强度 70 + 阈值 70 不让位。

**Q: 让位都命中了，模型还是按人设说话，是不是没生效？**
A: 这是「指令层优先级覆盖」，人格没被删掉，模型有一定概率仍然按人设走。所以是倾向不是保证。
想要更硬的效果开 `style_override_deep`，但那一轮 DeepSeek 的 system prompt 变了、
前缀缓存必然失效，输入按未命中价（30 倍）算。

**Q: 主动回复开了，群里一句话都没有，是不是坏了？**
A: 先按顺序排查：① 总开关和该群的会话开关；② 是不是在静默时段（默认 01:00–08:00）；
③ 最近 10 分钟是否少于 3 条消息（群太冷会直接跳过）；④ 今天是不是已经到日限 8 次；
⑤ 这个群的学习开关是不是关着——**主动回复的冷清判断读的是学习缓冲，关掉学习就没有主动回复**。
`/风格状态` 会显示「今日 N/8 · 下次评估 X 分钟后」，比猜快。

**Q: 开了主动回复之后出现两条回复？**
A: 大概率是 AstrBot 那边开了「群聊无需 @ 也回复」。插件命中插话时会 `should_call_llm(False)`
掐掉当前这条的原生回复，但 AstrBot 自己的策略仍可能再回一遍。把这个选项关掉。

**Q: 联网搜索配了 key 还是不会搜？**
A: 按这几条看：① `web_search_mode` 是不是 `plugin`（`inherit` 只是跟随 AstrBot、插件不管）；
② 搜出来的 key 是否真的取到了——`plugin` 模式下如果配不到 key，插件会把内置搜索工具
**一起摘掉**，表现就是完全不搜；③ 当天该群是不是已经用满 `web_search_daily_limit`（默认 20），
满额时工具根本不挂给模型；④ 这轮是不是主动插话——主动回复一律不搜索。

**Q: 消耗统计里的金额比我账单少？**
A: 对，它是**下限**。多轮工具调用中间那几次请求拿不到 usage，会漏计。插件自己发起的请求
（学习、判定、搜索次数）是精确的，每轮回复的 token 只能拿到最终响应那一份。

**Q: 想换 Tavily 划算吗？**
A: 先算额度：默认 20 次/群/天 × 10 群 × 30 天 = 6000 次/月，Tavily 免费额度是 1000 次/月。
要么把 `web_search_daily_limit` 压到 3 以下，要么继续用 DeepSeek（¥0.005/次，失败不计费）。
